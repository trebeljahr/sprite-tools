# CLI command reference

Full option list for each subcommand. Always run `sprite-tools <command> --help` for the authoritative, up-to-date version.

## `lint`

```
sprite-tools lint <input>
  [--cols N] [--rows N]            # auto-detected if omitted
  [--margin N] [--margin-x N] [--margin-y N]      # see Grid padding below
  [--spacing N] [--spacing-x N] [--spacing-y N]
  [--disable RULE]                 # repeatable; also accepts a comma-separated list
  [--only RULE]                    # repeatable; run only these rules
  [--set RULE.OPTION=VALUE]        # repeatable threshold override
  [--severity LEVEL]               # error|warning|info, default: info
  [--format FMT]                   # json|text, default: json
  [--exit-zero]                    # always exit 0, even when errors are found
  [-o FILE]                        # output file (default: stdout)
```

Runs nine rules over the sheet and reports structured findings. This is the command to run first on a sheet you did not make: it states the grid it detected, the frame count, and what is wrong before any other command commits to an interpretation. Output shape: [`LintReport`](/docs/reference/json-schemas#lint).

`--severity` trims findings below the level from the list; `summary` still counts the whole run, the same as the MCP tool's `min_severity`, so both surfaces emit the same JSON and you can see how much was held back. Error-severity findings are never filtered out, which keeps the exit code honest whatever you pass. `--only` wins first (every other rule off), `--disable` then turns individual rules off, and `--set` is applied last, so it can re-enable or re-severity a rule the earlier flags touched. Every part of a `--set` is validated: an unknown rule id, an unknown option name, a value of the wrong type, or a severity outside `error|warning|info` fails the command and names the valid alternatives, rather than being silently dropped. That matters because an unchecked string in a numeric threshold makes every comparison against it false, which inverts the gate instead of disabling it.

```bash
sprite-tools lint sheet.png --format text
sprite-tools lint sheet.png --cols 8 --rows 4 --severity warning
sprite-tools lint sheet.png --disable duplicate-frames,non-power-of-two
sprite-tools lint sheet.png --set alpha-fringe.minPixels=40 --set frame-bleed.severity=warning
sprite-tools lint sheet.png | jq '.findings[] | select(.severity=="error")'
```

### Exit codes

| Code | Meaning |
|---|---|
| `0` | No error-severity findings, or `--exit-zero` was passed |
| `1` | Error-severity findings present, **or** the tool itself failed |

Tell the two `1`s apart by stdout: a lint failure still writes a complete, valid report there, while a tool failure writes only `sprite-tools: <msg>` to stderr and nothing at all to stdout. The report is flushed before the non-zero exit, so `sprite-tools lint sheet.png | jq` works in CI. Warnings and infos never fail the build on their own — only `frame-bleed` is an error by default.

### Rules

Every rule is on by default. `--disable <id>` turns one off, `--set <id>.severity=<level>` re-grades it, and `--set <id>.<option>=<value>` moves a threshold. Fractions are shares of the frame's own size, not pixels.

| Rule | Default severity | Tunables (defaults) |
|---|---|---|
| `alpha-fringe` | `warning` | `opaqueAlpha=250`, `colourDistance=60`, `minPixels=24`, `minEdgeFraction=0.02` |
| `frame-bleed` | `error` | `minConfidence=0.5`, `minRunLength=3`, `minRunFraction=0.05`, `alphaThreshold=8` |
| `pivot-drift` | `info` | `preset=bottom-center`, `minFrames=3`, `maxDeviationFraction=0.25`, `maxStepFraction=0.15` |
| `duplicate-frames` | `info` | `threshold=0` (same meaning as `dedupe --threshold`), `maxComparisonPixels=32000000`, `maxGroupsReported=20` |
| `empty-cell` | `warning` (near-empty: `nearEmptySeverity=info`; trailing padding: `paddingSeverity=info`) | `alphaThreshold=0`, `nearEmptyFraction=0.005`, `contrastFactor=10` |
| `opaque-frame` | `warning` | `minTransparentFrames=1`, `minTransparentFraction=0.5` |
| `non-power-of-two` | `info` | `checkFrames=false` |
| `palette-bloat` | `info` | `minColors=256`, `targetColors=32`, `sampleStride=7`, `maxQuantizationError=4.0` |
| `palette-near-duplicates` | `info` | `maxColors=4096`, `maxDistance=2.0`, `minPixelsEach=8`, `maxPairs=20` |

### What each rule will not catch

Thresholds lean conservative on purpose — a rule that fires on healthy art is worse than a missing rule — so every rule has false negatives it accepts by design. A clean report means these nine rules found nothing, not that the sheet is correct.

| Rule | Known misses |
|---|---|
| `alpha-fringe` | A fringe keyed against a background colour that is not in the corners; a fringe on a sheet whose invisible pixels had their colour zeroed, where the background is unknowable rather than black; a fully opaque halo, which shows up as palette noise instead. Skipped outright when the sheet's alpha is strictly binary. |
| `frame-bleed` | Content that runs into a gutter or the outer margin without reaching the next cell, which the slicer silently crops; bleed between two cells that both happen to be padded at the seam; bleed where the true grid is so wrong that detection returned a single cell; bleed between two wall-to-wall opaque cells, which is indistinguishable from a gutterless tileset or full-cell art. Also skipped when detection confidence is below `minConfidence`. Seam pixels at or below `alphaThreshold` (default 8, about 3% opacity) are ignored, so a genuinely faint shadow or glow crossing a seam goes unreported unless you lower it. |
| `pivot-drift` | A sheet where every frame's pivot is equally wrong, so there is no outlier to find; multi-animation sheets where two animations legitimately anchor differently. Info by default because an intentional excursion — an airborne jump frame — is indistinguishable from a mis-anchored one. |
| `duplicate-frames` | Near-duplicates from lossy video or AI generation at the default `threshold=0`, which matches byte-identical visible pixels only; a raised threshold is a mean over the whole frame, so it starts merging frames whose small details differ. Frames that differ only by a small translation never match. A fuzzy pass is skipped, with the reason stated, once frames² × frame area exceeds `maxComparisonPixels`; the group list is capped at `maxGroupsReported`, though the true group total is always in the finding data. |
| `empty-cell` | An intentional blank spacer in the middle of a strip reads as a hole and still warns — that is what `--disable empty-cell` is for. Trailing padding is reported at `paddingSeverity` rather than as a warning. |
| `opaque-frame` | A frame whose background was keyed to a solid colour rather than to transparency looks intentional here and is not reported; an un-keyed frame on a sheet where the keyed frames are the minority reads as a tileset, which `minTransparentFraction` tunes. |
| `non-power-of-two` | Nothing here knows your target platform, so this is a note for you to judge, not a defect. |
| `palette-bloat` | Sheets that legitimately use gradients or anti-aliasing quantize badly and are left alone by design. |
| `palette-near-duplicates` | Photographic sources have too many colours to check and are skipped outright. Cannot tell a lossy re-encode from deliberate anti-aliasing or a gradient, which both produce colours one step apart. |

`sprite-tools lint --help` prints the same rule list with a one-line summary each. The [Sheet Lint page](/docs/web/lint) explains what each rule measures and how to react to it.

## `info`

```
sprite-tools info <input> [-o file]
```

Stats + detected grid + content bounds.

```json
{ "source", "width", "height", "opaquePixels", "opaqueFraction",
  "contentBounds": {x,y,width,height}|null,
  "grid": {cols, rows, confidence,
           "margin": {left,top,right,bottom},
           "spacing": {x,y}} }
```

## `detect`

```
sprite-tools detect <input> [-o file]
```

Just the grid:

```json
{ "source", "width", "height",
  "grid": {cols, rows,
           "margin": {left,top,right,bottom},
           "spacing": {x,y}},
  "confidence": 0..1 }
```

Confidence >= 0.5 is usually reliable. Below that the algorithm fell back to the cell-size heuristic.

`margin` and `spacing` are always present and are all zeros for a flush sheet. Non-zero values mean the sheet has a border and gutters — feed them back in as the flags under [Grid padding](#grid-padding-margins-and-gutters), or the frames will be off. Inference is conservative: it only reports padding when every content block on an axis is the same size and every gap between them is identical, so an unreadable sheet reports zeros rather than a guess.

## `slice`

```
sprite-tools slice <input>
  [--cols N] [--rows N]            # auto-detected if omitted
  [--out-dir DIR]                  # default: ./frames
  [--name PATTERN]                 # default: frame_%02d.png
  [--json FILE]                    # optional index JSON
  [--margin N] [--margin-x N] [--margin-y N]      # see Grid padding below
  [--spacing N] [--spacing-x N] [--spacing-y N]
```

Writes one PNG per cell. `--json` emits `{source, frameWidth, frameHeight, grid, frames: [{index, cell, path}, ...]}`.

## `trim`

```
sprite-tools trim <input>
  [--padding N]                    # pixels of transparent border to keep
  [--json FILE]                    # optional trim metadata
  [-o FILE]                        # output PNG (default: stdout)
```

Auto-crops transparent padding. JSON shape:

```json
{ "source", "sourceWidth", "sourceHeight",
  "trim": {x,y,width,height}, "paddingKept" }
```

## `aseprite`

```
sprite-tools aseprite <input>          # alias: ase
  [-o FILE]                        # sheet PNG (default: <basename>-sheet.png, - for stdout)
  [--json FILE]                    # metadata JSON (default: stdout)
  [--cols N]                       # sheet columns (default: every frame in one row)
  [--tag NAME]                     # export only the frames of this animation tag
  [--layer NAME]                   # repeatable: composite only these layers
  [--include-hidden]               # composite layers hidden in Aseprite too
  [--no-sheet]                     # metadata only, write no PNG
  [--scale N]                      # integer nearest-neighbor upscale, default 1
```

Reads an Aseprite working file (`.ase` or `.aseprite`) directly, so you do not need an export from Aseprite first. It composites every frame at canvas size, writes the frames as a row-major sheet PNG, and emits the document metadata a PNG does not carry: tags, per-frame durations, the layer tree, and the palette. `<input>` may be `-` to read the file from stdin. The magic number is checked, not the extension.

What gets composited:

- Every visible image layer, with its blend mode, layer opacity, and cel opacity. See [Aseprite files](/docs/reference/aseprite) for what is and is not supported.
- `--include-hidden` adds layers that are hidden in Aseprite, including layers inside a hidden group.
- `--layer` picks layers by exact name and is repeatable. Naming a group selects every layer inside it. An unknown name is an error that lists the available names.
- Reference layers are never composited, the same as an Aseprite export. `--include-hidden` and `--layer` do not bring them back.
- A `--layer` selection that renders no pixels exits 1 instead of writing an empty sheet. That happens when every named layer is a reference layer, or hidden without `--include-hidden`. When another named layer does render, each such layer adds a warning instead. See [Layer selection](/docs/reference/aseprite#layer-selection) for the messages.

Output files:

- Without `-o`, the sheet is written to `<basename>-sheet.png` in the current directory. With stdin input the default is `aseprite-sheet.png`.
- `-o -` writes the PNG to stdout. The JSON also goes to stdout by default, so `-o -` requires `--json FILE` (or `--no-sheet`). Otherwise the command exits with an error before it reads the input.
- `--no-sheet` writes no PNG. `-o` is then ignored and only the JSON is written.

JSON shape:

```json
{ "source": "sheet.png" | null,
  "sourceWidth": N | null, "sourceHeight": N | null,
  "asepriteFile": "hero.aseprite",
  "frameWidth", "frameHeight",
  "grid": {cols, rows, detected: false},
  "frameCount", "documentFrameCount",
  "canvas": {width, height},
  "colorDepth": 32 | 16 | 8,
  "pixelRatio": {width, height},
  "tag": "name" | null,
  "frameDurations": [ms, ...],
  "tags":   [{ name, from, to,
               direction: "forward"|"reverse"|"pingpong"|"pingpong-reverse",
               repeat, color: "#rrggbb"|null }, ...],
  "frames": [{ index, sourceIndex, durationMs }, ...],
  "layers": [{ index, name, type: "image"|"group"|"tilemap",
               opacity, blendMode, visible, effectivelyVisible, reference,
               childLevel, parentIndex }, ...],
  "palette": ["#rrggbb" | "#rrggbbaa", ...],
  "warnings": [...] }
```

- `source` is the sheet PNG this JSON describes, and `sourceWidth` / `sourceHeight` are its pixel size, including `--cols` and `--scale`. With `--no-sheet` all three are `null`. With `-o -` the PNG has no filename, so `source` is `null` and the size is still set.
- `asepriteFile` is the `.ase` / `.aseprite` file that was read, or `"-"` for stdin.
- `frameWidth` / `frameHeight` are the size of one cell in the PNG you got, so they include `--scale`. `canvas` is the unscaled Aseprite canvas.
- `grid` is the layout of the written sheet. `detected` is always `false`, because the layout comes from `--cols` and the frame count rather than from detection. Pass `grid.cols` and `grid.rows` to any sheet command that reads the PNG.
- `frameCount` counts the exported frames. `documentFrameCount` counts every frame in the file. `pixelRatio` is the file's pixel aspect ratio.
- `frameDurations` has one duration in milliseconds per exported frame. It is the same key the `tags` and `meta` commands write; see [JSON schemas](/docs/reference/json-schemas#framedurations). `gif --tags-json` and `export` read it.
- `frames[].durationMs` is the same per-frame duration. `frames[].sourceIndex` is the frame's index in the `.aseprite` document.
- `tags[].repeat` is the Aseprite repeat count. `0` means the file does not set one. Tags have no `fps`, because Aseprite stores timing only per frame.
- `layers[].visible` is the layer's own eye toggle. `effectivelyVisible` is `false` when the layer or any enclosing group is hidden. `reference` is `true` for a reference layer, which never renders. `layers[]` lists every layer, including groups, tilemap layers, and reference layers.
- `palette` is the palette in effect at frame 0. Entries are `#rrggbb`, or `#rrggbbaa` when the entry is not fully opaque. Indexed sprites whose palette changes between frames are still decoded per frame.

Because `source` names the sheet PNG, the JSON is a sheet metadata document. [`export`](#export) turns it into an engine file with no extra flags, and `gif hero-sheet.png --cols N --tags-json hero.json` plays its tags with the file's durations. A `--no-sheet` document needs `export --texture NAME`, because it names no image.

### Tag remapping

`--tag NAME` exports only that tag's frame range. Every tag range in the JSON is then rebased onto the exported frames, so the numbers index the sheet you got:

- `from` and `to` become 0-based positions in the exported sheet.
- A tag that only partly overlaps the exported range is clipped to it.
- A tag that lies entirely outside the exported range is left out.
- `frames[].sourceIndex` still points back into the original document.

For example, in a file with a `reverse` tag on frames 4–7, `--tag reverse` gives a 4-frame sheet, `"tags": [{"name": "reverse", "from": 0, "to": 3, ...}]`, and `sourceIndex` values 4 to 7. Without `--tag`, ranges are the file's own. An unknown tag name is an error that lists the available tags.

### Warnings

Some content in a file can decode only partly. A tilemap layer, a skipped chunk type, or a damaged cel are examples. The command does not fail on these. It writes one line per warning to stderr as `sprite-tools: warning: <message>`, and it also puts the same messages in the JSON `warnings` array. The stderr lines appear when stdout is piped into `jq` or another command, so a partial decode is always visible. The exit code stays 0. The [Aseprite files](/docs/reference/aseprite#warnings) page lists the common messages.

A file that cannot be read at all exits 1 with a message. Examples are a bad magic number, an unsupported colour depth, and a file cut off partway through a frame.

```bash
sprite-tools ase hero.aseprite                                     # hero-sheet.png + JSON on stdout
sprite-tools ase hero.aseprite -o hero-sheet.png --json hero.json
sprite-tools ase hero.aseprite --cols 4 --scale 2 -o hero-sheet.png --json hero.json
sprite-tools ase hero.aseprite --tag run -o run.png --json run.json
sprite-tools ase hero.aseprite --layer body --layer sword -o armed.png --json armed.json
sprite-tools ase hero.aseprite --no-sheet | jq '.tags'
sprite-tools ase hero.aseprite -o - --json hero.json | sprite-tools collision - --cols 8 --rows 1
sprite-tools export hero.json --format godot -o hero.tres           # hero.json from the second line
```

The `tags` key has the same name as the `tags` command's output, with a different item shape: it has `repeat` and `color` and no `fps`. If you merge the two with `jq -s 'add'`, the file that comes last wins that key. The `source`, `sourceWidth`, `sourceHeight`, `grid`, `frameWidth`, `frameHeight`, and `frameDurations` keys follow the same rule. A document written with `-o -` has `source: null`, so a merge with it last also has `source: null`, and `export` then needs `--texture`. The [Aseprite recipe](/docs/cli/recipes#aseprite-file-to-sheet-collision-and-pivots) merges this JSON with `collision` and `pivot` output.

## `tags`

```
sprite-tools tags <input>
  [--cols N] [--rows N]
  [--tag "name=from-to[:fps[:direction]]"]  # repeatable
  [--fps N]                        # default FPS
  [--duration "index=ms"]          # repeatable; also "from-to=ms"
  [-o FILE]
```

Direction is `forward` (default), `reverse`, or `pingpong`. Example:

```
--tag idle=0-5
--tag run=6-11:12:pingpong
--tag attack=12-18:24
```

`--duration` gives one frame an explicit hold time in milliseconds — `--duration 3=250` for a single frame, `--duration 2-5=250` for an inclusive range. Indices are **sheet** frame indices, not offsets within a tag: durations live globally per frame (see [JSON schemas](/docs/reference/json-schemas#framedurations)). The flag is repeatable and later specs win where ranges overlap.

Frames you never name keep no explicit hold and play at the `fps` of whichever tag is running them, so `--duration` and `--fps` compose:

```bash
sprite-tools tags hero.png --tag idle=0-5 --fps 12 --duration 0=250 --duration 3-4=180
```

The output grows a top-level `frameDurations` array (one entry per frame, `null` where unset) only when at least one frame has an explicit hold. Without any `--duration`, the JSON is exactly what it was before the flag existed.

## `nine-slice`

```
sprite-tools nine-slice <input>
  [--cols N] [--rows N]
  [--left N] [--right N] [--top N] [--bottom N]   # explicit insets
  [--alpha N]                      # alpha threshold, default 8
  [--tolerance N]                  # 0..1 adjacent-line difference, default 0.02
  [--min-middle N]                 # smallest stretchable middle, default 1
  [--from-9patch]                  # read the insets off an Android .9.png border
  [--emit-9patch FILE]             # also write a .9.png carrying the insets
  [--preview FILE]                 # also write a stretched PNG to eyeball
  [--preview-size WxH]             # size for --preview (default: 3x the frame)
  [-o FILE]                        # JSON (default: stdout)
```

Emits the four stretch insets plus the nine regions they imply, per frame. Sides you pass are used as-is; sides you leave out are guessed, so you can pin the one you know and let the rest be filled in.

That guess is a starting point derived from variance profiles: it looks for the longest run of near-identical adjacent columns and rows and calls that the stretchable middle. It holds up on panels with an obviously flat or repeated middle and falls apart on busy or gradient artwork, where it reports zeros and a `confidence` of 0. Pass the insets yourself when that happens — `--left` / `--right` / `--top` / `--bottom` are the real interface.

`--preview` is the check that actually matters: it writes the frame stretched through the current insets so you can open it and see whether the corners survived. `--from-9patch` skips guessing entirely and decodes the 1 px Android marker border instead, which is exact — one contiguous black run per edge is supported, and a multi-run `.9.png` is rejected rather than approximated. `--emit-9patch` and `--preview` operate on frame 0 of a multi-frame sheet.

```bash
sprite-tools nine-slice panel.png -o panel.json
sprite-tools nine-slice panel.png --left 8 --right 8 --top 8 --bottom 8 -o panel.json
sprite-tools nine-slice panel.png --top 12 --tolerance 0.05     # detect the other three sides
sprite-tools nine-slice panel.png --preview panel-192x96.png --preview-size 192x96
sprite-tools nine-slice panel.9.png --from-9patch -o panel.json
sprite-tools nine-slice panel.png --left 8 --right 8 --top 8 --bottom 8 --emit-9patch panel.9.png
```

Output JSON has a `nineSlice` array with `{index, cell, insets, detected, confidence, regions}` per frame — see the [JSON schemas](/docs/reference/json-schemas) and the [Nine-slice page](/docs/web/nine-slice).

## `meta`

```
sprite-tools meta <input>
  [--cols N] [--rows N]
  [--collision] [--alpha N] [--tolerance N] [--convex-hull]
  [--pivot PRESET] [--pivot-x N] [--pivot-y N]
  [--tag SPEC ...] [--fps N] [--duration SPEC ...]
  [--nine-slice]
  [--nine-slice-left N] [--nine-slice-right N]
  [--nine-slice-top N] [--nine-slice-bottom N]
  [-o FILE]
```

One-shot: emits a single JSON with whichever sections (`collision`, `pivots`, `tags`, `nineSlice`) you opted into.

`--nine-slice` adds the `nineSlice` section. The `--nine-slice-*` flags pin individual insets; sides you leave out are guessed the same way the `nine-slice` command guesses them, with the same limits, at the default alpha threshold, tolerance, and minimum middle. Use the `nine-slice` command directly when you need to tune those, render a `--preview`, or read a `.9.png`.

`--duration` behaves exactly as it does on [`tags`](#tags) and adds the same top-level `frameDurations` array to the combined document.

## `dedupe`

```
sprite-tools dedupe <input>
  [--cols N] [--rows N]            # auto-detected if omitted
  [--margin N] [--margin-x N] [--margin-y N]      # see Grid padding below
  [--spacing N] [--spacing-x N] [--spacing-y N]
  [--threshold N]                  # max mean RGBA difference, 0-255, default 0 (byte-identical only)
  [--tags FILE]                    # tags JSON to rewrite through the remap
  [--tags-out FILE]                # also write the rewritten tags as a standalone tags JSON
  [--respect-tags]                 # never merge across a tag boundary (requires --tags)
  [--sheet FILE]                   # also write the deduped sheet PNG ('-' for stdout)
  [--sheet-cols N]                 # columns for --sheet, default: the input's columns
  [-o FILE]                        # JSON (default: stdout)
```

Finds duplicate and near-duplicate frames in a sheet and, with `--sheet`, writes the sheet without them. Video extracted at a fixed FPS and AI-generated frames often repeat the same pose many times over.

**Threshold.** threshold is the mean absolute difference per RGBA channel on a 0-255 scale, averaged over every channel of every pixel. 0 requires byte-identical frames. 1 means the average channel differs by 1/255 (~0.4%), the scale of rounding noise from lossy video compression or canvas alpha premultiplication. 2-4 absorbs a handful of stray pixels. Above ~8 visibly different poses start collapsing.

The comparison is inclusive: a frame merges when its distance is `<=` the threshold. Start at 0, then raise it one step at a time and read the `distances` in `groups` to see how close each merge was.

**Matching rules.**

- Alpha counts. An alpha difference adds to the distance like any other channel. At threshold 0 an alpha-only change is never a duplicate. At a higher threshold it merges once its distance is at or below the threshold. RGB under a fully transparent pixel is read as 0, so colour nobody can see never counts.
- Frames of different sizes never match.
- Byte-identical frames always merge first. Near-duplicates are matched after that, only when `--threshold` is above 0.
- Matching is greedy, in source order. Each frame is compared with the first frame of every group found so far, and joins the first group within the threshold. It is never compared with the other members of a group. So if a matches b and b matches c, but a does not match c, then a and c stay apart.
- Frames are never reordered. The frame kept for a group is always the one with the lowest index.

**Tags.** Removing a frame renumbers every frame after it. Animation tags are frame ranges, so a tags file written for the old sheet points at the wrong frames after a dedupe. Pass `--tags` with the JSON that `sprite-tools tags` writes (or a bare array of `{name, from, to, direction?, fps?}`), and every range is rewritten through `remap`. `from` and `to` must be integers, and a tag needs a non-empty `name`; anything else is an error. The rewritten tags are always in the main JSON under `tags`. `--tags-out` also writes them on their own as `{ source, frameWidth, frameHeight, grid, frameCount, tags, frameDurations?, warnings }`, with `grid` and `frameCount` describing the deduped sheet, so the file works as input for other commands. `source` is the `--sheet` file, or the input sheet when `--sheet` names no file, and then a warning says the tags match no sheet on disk. `--tags-out` without `--tags` is an error.

Each tag's old range is walked from its lower to its higher index. Every old index maps to the new index of its kept frame, and runs of the same new index collapse into one. That collapse is intended: adjacent duplicate frames make the animation shorter. Name, `direction`, and `fps` are kept. A top-level `frameDurations` array (milliseconds per old frame) is carried into `--tags-out`: each kept frame takes the first explicit hold in its group, lowest index first. Holds of collapsed frames are not added together.

A rewritten range can come back non-contiguous, for two reasons. A frame inside the range matched a frame outside it: the neutral pose that opens `run` can be byte-identical to a frame in `idle`, so `run` now starts with idle's copy. Or the tag repeats one of its own poses non-adjacently, as a walk cycle filmed over two loops does. Frames are not reordered or copied to close the gap, and the range is not widened. Instead the tag gets:

- `frames` — the exact ordered list of new indices the tag plays. This is the authoritative field.
- `from` / `to` — the lowest and highest index in `frames`, for tools that only read ranges. They do not describe what the tag plays.
- `contiguous: false`
- a warning that names the tag and the cause.

`--respect-tags` confines merging to within each tag, so a frame can never merge with a frame from another animation. Frames outside every tag share one group of their own. Where tags overlap, the overlapping frames belong to the first tag listed, and a warning says so. This removes the cross-tag cause of gaps. A tag can still come back non-contiguous when two non-adjacent frames inside it match each other, for example frames 0 and 2 identical and frame 1 different.

`warnings` also reports a tag that shrank, a tag that collapsed to a single frame, and a tag whose range fell partly outside the sheet (the range is clamped). A tag whose range lies entirely outside the sheet comes back with an empty `frames` array and `contiguous: false`.

**Sheet.** `--sheet` writes the kept frames in source order, `--sheet-cols` columns wide. Rows are `ceil(uniqueCount / cols)`. Cells after the last frame are fully transparent. `--sheet -` needs `-o FILE` for the JSON, so the PNG and the JSON do not both go to stdout.

```json
{ "source", "frameWidth", "frameHeight",
  "grid": {cols,rows,detected},          // the input grid
  "frameCount",
  "method": "exact"|"mae",               // "exact" when threshold is 0
  "threshold", "uniqueCount", "removedCount",
  "keptIndices": [oldIndex, ...],        // ascending
  "remap": [newIndex, ...],              // one entry per old frame: the new index of its kept frame
  "groups": [{ "keep", "duplicates": [...], "distances": [...] }],   // groups with >= 1 duplicate
  "tags": [{ "name", "from", "to", "direction"?, "fps"?,
             "frames": [...], "contiguous" }],                    // only with --tags
  "warnings": [string, ...] }            // only with --tags
```

`distances[i]` is the distance between `duplicates[i]` and `keep`. 0 means byte-identical. `--threshold` must be 0 or more.

```bash
# Report exact duplicates only
sprite-tools dedupe sheet.png

# Absorb faint noise, write the clean sheet
sprite-tools dedupe sheet.png --threshold 1 --sheet clean.png -o dedupe.json

# Rewrite a tags file for the deduped sheet, without merging across tags
sprite-tools dedupe sheet.png --threshold 1 --tags hero-tags.json --respect-tags \
  --tags-out hero-tags-deduped.json --sheet clean.png -o dedupe.json
```

The MCP tool is `sprite_find_duplicates`. In the web app, use **Select unique** in [Sheet Builder](/docs/web/spritesheet) or the duplicate step in [Background Removal](/docs/web/background-removal).

## `palette`

```
sprite-tools palette <input>
  [--cols N] [--rows N]
  [--colors N]                     # default 8
  [--swap "#RRGGBB=#RRGGBB"]       # repeatable
  [--ramps]                        # include detected shading ramps in the JSON
  [--ramp-tolerance DEG]           # hue slack for ramp detection, default 25
  [--ramp "#MEMBER=#NEWBASE"]      # repeatable: re-tint a whole ramp
  [--variants FILE]                # variant-set JSON (version 1)
  [--hue-variants N]               # instead: N evenly spaced hue rotations
  [--hue-step DEG]                 # override the even spacing
  [--out-dir DIR]                  # variant PNGs land here, default .
  [--name BASE]                    # filename base, default: input basename
  [--manifest FILE]                # write the variant manifest JSON
  [--image FILE]                   # also write recolored PNG
  [-o FILE]                        # JSON
```

A **ramp** is a run of shades of one material — a shirt is four related colors, not one. `--ramp` moves all of them at once in OKLCH, preserving the lightness steps and the artist's hue drift, so it is not the same as four `--swap`s picked by eye. `<member>` may be **any** hex in the ramp, not just its most saturated entry. Ramp remaps and `--swap` merge into the same `swaps` output and the same `--image`; an explicit `--swap` wins for the same source color.

`--variants` and `--hue-variants` are mutually exclusive. Either one writes `<out-dir>/<base>_<slug>.png` per variant, stitched back to the source grid for sheets. `--hue-variants 8` emits 8 files including the 0° original, named `hero_hue000.png` … `hero_hue315.png`. `--manifest` requires one of them. A variant set's optional `colors` pins the palette size it was authored against unless you pass `--colors` explicitly.

The JSON gains `ramps` (and `options.rampTolerance`) with `--ramps` or any ramp/variant flag, and `variants` when variants were generated. Without those flags the output is byte-for-byte what it always was:

```json
{ "source", "frameWidth", "frameHeight", "grid",
  "options": { "colors": 12, "rampTolerance": 25 },
  "palette": ["#rrggbb", ...],
  "swaps": [{ "from": "#rrggbb", "to": "#rrggbb" }, ...],
  "ramps": [{ "index", "base", "colors": ["#rrggbb", ...], "achromatic" }, ...],
  "variants": [{ "name", "slug", "file", "hueShift", "swaps" }, ...] }
```

Variant-set file shape (camelCase — the MCP tool takes the same fields in snake_case):

```json
{
  "version": 1,
  "colors": 12,
  "variants": [
    { "name": "Team Red", "ramps": [{ "base": "#4d7faf", "to": "#af4d4d" }] },
    { "name": "Referee",  "ramps": [{ "base": "#4d7faf", "to": "#3d3d3d" }],
                          "swaps": { "#af4d4d": "#f2f2f2" } },
    { "name": "Ghost",    "hueShift": 180 }
  ]
}
```

Two worked examples:

```bash
# See the ramps first, then move the blue one to red across the whole sheet
sprite-tools palette hero.png --colors 12 --ramps | jq '.ramps'
sprite-tools palette hero.png --colors 12 \
  --ramp '#4d7faf=#af4d4d' --image hero-red.png

# 8 enemy tints + a manifest an importer can read
sprite-tools palette hero.png --hue-variants 8 \
  --out-dir ./variants --name hero --manifest ./variants/hero.json
```

See the [Palette page](/docs/web/palette) for why the math runs in OKLCH rather than HSL.

## `chroma`

```
sprite-tools chroma <input>            # alias: remove-bg
  [--mode transparent|solid]       # default: transparent
  [--similarity N]                 # background distance, default 30
  [--softness N]                   # feather band width, default 10
  [--spill N]                      # edge desaturation reach, default 20
  [--choke N]                      # erode the matte N px, default 1
  [--color #RRGGBB]                # colour to key out (default: auto-detect from corners)
  [--fill #RRGGBB]                 # fill colour for --mode solid (default: auto-sample corners)
  [--trim]                         # auto-crop the transparent border afterwards
  [-o FILE]                        # output PNG (default: stdout)
```

Chroma-key background removal on the whole image, treated as one frame. In `transparent` mode the keyed colour becomes transparency; without `--color` it is voted from the four corners. In `solid` mode the background is replaced by `--fill`, or by a gradient blended from the four corner colours when `--fill` is omitted — the output is fully opaque, and `--color`, `--spill`, and `--choke` are ignored. `--trim` crops to the opaque bounding box with no padding.

Defaults match the web app's [Background Removal](/docs/web/background-removal) page.

```bash
sprite-tools chroma hero.png --color '#00ff00' --similarity 60 --trim -o hero-cut.png
sprite-tools chroma hero.png --mode solid --fill '#ffffff' -o hero-white.png
```

For sheets, key each cell with the MCP tool `sprite_remove_background`, or `slice` first and loop.

## `pixelate`

```
sprite-tools pixelate <input>
  [--cols N] [--rows N] [--auto-grid]
  [--pixel-size N]                 # source pixels per output pixel, default 4
  [--colors N]                     # quantization, default 16
  [--palette ID]                   # none|gameboy|gameboy-pocket|mono|pico8|cga|nes
  [--dither]                       # Floyd-Steinberg
  [--alpha-threshold N]
  [--no-upscale]                   # keep native low-res output
  [--upscale-algo ID]              # nearest|scale2x|scale3x|eagle|xbr, default nearest
  [--upscale-factor N]             # explicit magnification, default 1 (off)
  [-o FILE]                        # PNG (default: stdout)
```

Two size controls that are easy to confuse. `--upscale` (on by default, disabled with `--no-upscale`) only restores the pixelated frame to the **source** size with blocky nearest-neighbor pixels — it can never make a sprite bigger than the input. `--upscale-factor N` with `N > 1` is real magnification by an integer factor, and it **replaces** that restore step entirely, so nothing is scaled twice and `--no-upscale` becomes irrelevant. At the default `N = 1` the old behavior is untouched.

`--upscale-algo` picks the filter used by `--upscale-factor`; it does nothing at factor 1. The algorithm's native step is applied as often as it divides the factor evenly and the remainder falls back to nearest-neighbor — `scale2x --upscale-factor 4` is two Scale2x passes, `--upscale-factor 6` is one pass then nearest ×3, `scale3x --upscale-factor 9` is two Scale3x passes. Every filter only copies existing source pixels, so no new colors appear and transparency is preserved exactly. See [Pixelate](/docs/web/pixelate) for what each one looks like and when it is worth using — for a lot of pixel art `nearest` is the right answer.

```bash
# Pure upscale: no downscale, no quantization, just magnify pixel art 4x with Scale2x
sprite-tools pixelate hero.png --pixel-size 1 --colors 0 --upscale-algo scale2x --upscale-factor 4 -o hero-4x.png

# Game Boy pixel art, then 2x with xBR
sprite-tools pixelate hero.png --pixel-size 4 --palette gameboy --upscale-algo xbr --upscale-factor 2 -o hero-gb-2x.png
```

## `outline`

```
sprite-tools outline <input>
  [--cols N] [--rows N]            # auto-detected if omitted
  [--style outer|inner]            # default: outer
  [--width N]                      # outline thickness in px, default 1
  [--color #RRGGBB]                # default: #000000
  [--opacity N]                    # 0..1, default 1
  [--connectivity 4|8]             # growth neighbourhood, default 8
  [--alpha-threshold N]            # 0..255, default 8
  [--overflow expand|clip]         # default: expand
  [--no-outline]                   # skip the outline (shadow only)
  [--shadow]                       # enable the drop shadow
  [--shadow-offset X,Y]            # default: 2,2
  [--shadow-color #RRGGBB]         # default: #000000
  [--shadow-opacity N]             # 0..1, default 0.5
  [--shadow-blur N]                # box-blur radius in px, default 0
  [--json FILE]                    # optional metadata JSON
  [-o FILE]                        # output PNG (default: stdout)
```

Adds an outline and/or a drop shadow. Both come from the same pass: a bounded multi-source breadth-first search over the alpha mask gives the distance of every pixel from the sprite, and the outer band, the inner band, and the shadow silhouette are all read off it.

A pixel counts as sprite when its alpha is **above** `--alpha-threshold`. `--style outer` colours the pixels 1..`--width` steps outside that mask and composites the sprite back on top, so anti-aliased edge pixels blend over the outline instead of being cut. `--style inner` replaces the pixels 1..`--width` steps inside the mask and never changes the canvas size. `--connectivity 8` grows diagonally (square corners); `4` grows in Manhattan steps (mitred corners).

The shadow is the final opaque footprint — the sprite grown by the outer outline, when one is enabled — translated by `--shadow-offset`, box-blurred by `--shadow-blur`, tinted, and drawn underneath everything. Composite order is shadow, outer outline, sprite, inner outline — an inner band is drawn last, over the sprite edge.

`--overflow expand` (the default) grows the canvas by exactly the margin the effect needs so nothing is cropped; `--overflow clip` keeps the source dimensions and lets the effect run off the edge. For a sheet the margin is computed once from the options and applied to every cell, so the grid stays uniform.

JSON shape:

```json
{ "source", "sourceWidth", "sourceHeight",
  "grid": {cols,rows},
  "frameWidth", "frameHeight", "outputWidth", "outputHeight",
  "margin": {left,top,right,bottom},
  "options": {...} }
```

```bash
sprite-tools outline hero.png --width 2 --color '#1a1a2e' -o hero-outlined.png
sprite-tools outline hero.png --style inner --width 1 --color '#ffffff' -o hero-rim.png
sprite-tools outline hero.png --no-outline --shadow --shadow-offset 3,4 --shadow-blur 2 -o hero-shadow.png
sprite-tools outline sheet.png --cols 8 --rows 4 --width 1 --shadow --overflow clip -o sheet-fx.png
```

Defaults match the web app's [Outline & Shadow](/docs/web/outline) page.

## `export`

```
sprite-tools export <meta.json>
  -f, --format godot|unity|aseprite|phaser   # required
  [--variant V]                    # godot: spriteframes|atlastextures
                                   # aseprite/phaser: hash|array
  [--texture NAME]                 # texture filename recorded in the output
  [--name-prefix STEM]             # frame-name stem (grid inputs only)
  [--fps N]                        # FPS for frames no tag covers, default 10
  [--res-path PATH]                # [godot] res:// path, default res://<texture>
  [--no-loop]                      # [godot] mark animations non-looping
  [--ppu N]                        # [unity] pixels per unit
  [--asset-path PATH]              # [unity] project-relative path — seeds the guid
  [--guid HEX]                     # [unity] reuse an existing .meta guid
  [--no-physics-shape]             # [unity] omit collision polygons
  [--pivots omit|slices]           # [aseprite] carry pivots as a slice, default omit
  [-o FILE]                        # output file (default: stdout)
```

Metadata JSON in, engine-native file out. No pixels are touched — the input is a document some earlier command already produced. `<meta.json>` accepts `-` to read the document from stdin. For a grid document, the width and height of the `source` PNG are read from its header when the file exists (relative to the working directory, then to the JSON file). The texture size comes from there, and a grid that does not match it is an error. `-o` naming the input file is refused, because it would overwrite the metadata.

Input can be a `meta` output, a `jq -s add` merge of `collision`/`pivot`/`tags`, an `atlas --json` manifest, or a header merged with a manifest. Missing sections are skipped; pivots, polygons and tags attach by frame index.

| Format | Output |
| --- | --- |
| `godot` | `.tres` text resource — a `SpriteFrames`, or one `AtlasTexture` per frame |
| `unity` | `TextureImporter` YAML for `<texture>.png.meta` |
| `aseprite` | `{ frames, meta: { size, frameTags, slices? } }` |
| `phaser` | `{ frames, animations, meta }` — Phaser 3 / PixiJS atlas |

```bash
sprite-tools export hero.json --format godot -o hero.tres
sprite-tools export hero.json --format unity --asset-path 'Assets/Art/hero.png' --ppu 32 -o hero.png.meta
sprite-tools export hero.json --format phaser --variant array -o hero-atlas.json

# straight out of a metadata pass
sprite-tools meta hero.png --collision --pivot bottom-center --tag idle=0-5 \
  | sprite-tools export - --format aseprite -o hero-aseprite.json
```

A flag that belongs to another format is an error, not a silent no-op: `--ppu` on a Godot export exits 1 with `--ppu only applies to --format unity, not godot`. `--variant` on a Unity export is an error too, since Unity has one output shape.

The texture filename is `--texture`, else the manifest's `atlas`, else the basename of `source`. A grid document with `source: null` (for example `aseprite --no-sheet` output) names no image, so it is an error unless `--texture` is given. Frames no tag covers show for `round(1000 / --fps)` ms. With no tags at all, Godot gets one animation named `default` over every frame.

For PixiJS, keep the default `--variant hash`: Pixi needs `frames` to be an object, and an array loads with frames named `"0"`, `"1"`, … instead of your names.

`--variant atlastextures` is one file per frame, so `-o` is a **directory** there — it is created if missing, the files are written into it, and the count goes to stderr. An `-o` that ends in `.tres` and is not an existing directory is refused, because it would create a folder with a file's name. To stdout the same variant is a `; <filename>`-delimited bundle, which is a preview and not importable.

Two things the command deliberately does not do: it does not name the Unity sidecar for you (it must end up as `<texture>.png.meta` next to the PNG), and it does not read an existing `.meta` back — overwriting one without passing its old `--guid` detaches every reference to that asset in the Unity project.

See [engine export](/docs/reference/engine-export) for the generated output of each format, the coordinate conventions, and the per-format limitations.

## `gif`

```
sprite-tools gif <input>
  [--cols N] [--rows N]
  [--fps N]
  [--scale N]                      # integer nearest-neighbor upscale
  [--alpha-threshold N]
  [--reverse] [--pingpong]
  [--tags-json FILE]               # read frameDurations from a tags/meta JSON
  [--duration "index=ms"]          # repeatable; also "from-to=ms"
  [-o FILE]                        # GIF
```

`--tags-json` reads the `frameDurations` array out of a `tags` or `meta` JSON, so a sheet timed once exports with the same holds. `--duration` sets holds inline with the same `index=ms` / `from-to=ms` syntax as the [`tags`](#tags) command, and wins over `--tags-json` for the frames it names. Frames with no explicit hold use `--fps`.

```bash
sprite-tools tags hero.png --tag idle=0-5 --duration 0=250 -o hero-tags.json
sprite-tools gif  hero.png --tags-json hero-tags.json --scale 3 -o hero.gif
```

### GIF timing resolution

GIF stores frame delay in hundredths of a second, so every duration is rounded to the nearest **10 ms** and floored at **20 ms** (browsers clamp shorter delays up to roughly 100 ms). A 125 ms hold is written as 130 ms; a 5 ms hold becomes 20 ms. The result is close to the authored timing, not exact — the tags JSON stays the precise record.

## Grid padding (margins and gutters)

Sheets from Kenney, Tiled, TexturePacker, and most itch.io packs are not flush: there is a border around the sheet and a 1–2px gutter between cells. Slicing one of those as `width / cols` puts every cell boundary a little further right and down than it belongs, so each frame picks up a strip of its neighbour. The result looks almost right — which is why it usually goes unnoticed until the sprite is moving on screen.

Every command that takes `--cols` / `--rows` also takes:

```
  [--margin N]                     # border on all four sides, px
  [--margin-x N]                   # left+right border (beats --margin)
  [--margin-y N]                   # top+bottom border (beats --margin)
  [--spacing N]                    # gutter between cells, px
  [--spacing-x N]                  # horizontal gutter (beats --spacing)
  [--spacing-y N]                  # vertical gutter (beats --spacing)
```

That is `slice`, `collision`, `pivot`, `tags`, `meta`, `palette`, `pixelate`, `normal-map`, and `gif`. Values are whole pixels, zero or more. The more specific flag wins per axis, so `--margin 2 --margin-x 4` means a 4px left/right border and a 2px top/bottom one.

Internally the border is four-sided, and `detect` can report an asymmetric one (a sheet whose trailing border differs from its leading one), but no flag addresses a single side — on such a sheet, omit the margin flags and let detection fill all four in.

Cell size becomes `(width - marginLeft - marginRight - (cols - 1) * spacingX) / cols`, and column *c* starts at `marginLeft + c * (cellW + spacingX)`. Rows work the same way with the vertical values.

Unless you pass both `--cols` and `--rows`, detection runs and fills in the margin and spacing too — any flag you did pass wins over the detected value for that side or axis. Pass both and detection is skipped entirely, so padding you did not state is zero rather than inferred. Detected padding is only a hint: if it does not tile the sheet it is dropped rather than raised as an error, so a sheet that slices today keeps slicing. Padding you typed is an assertion, and its fit error propagates.

Commands that write a sheet back out (`palette --image`, `pixelate`, `normal-map`) restitch it flush. Padding is an input property of the source sheet; the output is packed edge to edge.

### Divisibility

The rule is deliberately asymmetric:

- **No padding given** — legacy behaviour. Cell size is `floor(width / cols)`, and a sheet whose width the column count does not divide silently loses the remainder off the right and bottom edges. Every sheet that slices correctly today keeps slicing exactly the same way.
- **Padding given** — you have asserted an exact geometry, so numbers that do not add up are an error rather than a silent mis-slice, and the message names them:

```
grid does not fit: width 270 with marginLeft 0, marginRight 0, spacingX 3 leaves 249px
for 8 columns (31.13px each) — not a whole number. Try marginRight 1 for 31px cells, or
columns 3 (divisors of 249).
```

Read that as a diagnosis rather than a literal command line: the flags are per-axis, so a suggestion like `marginRight 1` is telling you the sheet has one spare pixel on the right — adjust `--cols`, `--spacing-x`, or crop the sheet.
