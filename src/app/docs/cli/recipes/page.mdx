# CLI recipes

Copy-paste pipelines for common workflows.

## One file with all metadata, merged

```bash
sprite-tools meta hero.png \
  --collision --tolerance 4 \
  --pivot bottom-center \
  --tag idle=0-3 \
  --tag run=4-7:12 \
  --tag attack=8-11:18 \
  -o hero.json
```

One pass, one file. No `jq`.

## One file, three commands, merged with jq

If you want per-tool JSON on disk too:

```bash
sprite-tools collision hero.png -o c.json
sprite-tools pivot hero.png --preset bottom-center -o p.json
sprite-tools tags hero.png --tag idle=0-3 --tag run=4-7 -o t.json

jq -s 'add' c.json p.json t.json > hero.json
```

## Auto-detect grid, pipe into another command

```bash
GRID=$(sprite-tools detect sheet.png | jq -r '.grid | "--cols \(.cols) --rows \(.rows)"')
sprite-tools collision sheet.png $GRID --tolerance 4 -o c.json
```

## Pin nine-slice borders on a folder of UI panels

Every panel in a UI kit usually shares one border thickness, and you already know what it is. Pass it rather than letting the detector guess:

```bash
mkdir -p ui-meta
for f in ui/panels/*.png; do
  name=$(basename "$f" .png)
  sprite-tools nine-slice "$f" \
    --left 8 --right 8 --top 8 --bottom 8 \
    -o "ui-meta/${name}.json"
done
```

Drop the four flags to get a guess instead — it works on panels with a flat or repeated middle and not much else, so look at the numbers and at a rendered preview before shipping them:

```bash
sprite-tools nine-slice ui/panels/dialog.png \
  --preview /tmp/dialog-stretched.png --preview-size 320x120 \
  | jq '.nineSlice[0] | {insets, confidence}'
```

For an Android `.9.png`, read the marker border instead of guessing at all:

```bash
sprite-tools nine-slice ui/panels/button.9.png --from-9patch -o button.json
```

## Slice a tileset that has a border and gutters

Kenney, Tiled, and most itch.io packs ship sheets with an outer border and a 1–2px gutter between cells. Slicing those flush bleeds a strip of the neighbouring tile into every frame — it looks almost right, so it survives until the tile is on screen. `detect` reports the padding it can infer, and the flags take it back:

```bash
sprite-tools detect tileset.png
# {
#   "grid": { "cols": 8, "rows": 6,
#             "margin": {"left":1,"right":1,"top":1,"bottom":1},
#             "spacing": {"x":2,"y":2} },
#   "confidence": 0.9
# }

sprite-tools slice tileset.png \
  --cols 8 --rows 6 --margin 1 --spacing 2 \
  --out-dir tiles
```

Or hand the whole thing over with `jq`:

```bash
PAD=$(sprite-tools detect tileset.png | jq -r '.grid |
  "--cols \(.cols) --rows \(.rows) --margin-x \(.margin.left) --margin-y \(.margin.top)"
  + " --spacing-x \(.spacing.x) --spacing-y \(.spacing.y)"')
sprite-tools slice tileset.png $PAD --out-dir tiles
```

`--margin-x` sets the left *and* right border, so that one-liner flattens a sheet whose trailing border differs from its leading one — check `.margin.right` and `.margin.bottom` before trusting it. The flags are per-axis by design and cannot express an asymmetric border; when `detect` reports one, leave the margin flags off and let detection supply all four sides itself.

Dropping the flags entirely works too — `slice` runs the same detection and uses the inferred padding when it tiles the sheet. Pass them when you know the numbers (the pack's README usually says) or when detection reports zeros on a sheet you can see has gutters.

Once you state a margin or spacing, the numbers have to divide exactly, and a mismatch is an error naming the actual pixel counts instead of a quietly wrong slice. With no padding flags nothing changes: the cell size is still `floor(width / cols)`. See [Grid padding](/docs/cli/reference#grid-padding-margins-and-gutters).

## Convert a regular sprite to Game Boy style

```bash
sprite-tools pixelate hero.png \
  --pixel-size 4 --palette gameboy --dither \
  -o hero-gb.png
```

## Key a flat background out, then trim in the same pass

```bash
sprite-tools chroma render.png \
  --color '#00ff00' --similarity 60 --spill 30 --choke 1 --trim \
  -o hero.png
```

Drop `--color` to let it vote the background colour from the four corners. Works per image, not per cell — slice a sheet first if you need per-frame keying.

## Batch: key a folder of renders, then pack them into an atlas

```bash
mkdir -p cut
for f in renders/*.png; do
  sprite-tools chroma "$f" --trim -o "cut/$(basename "$f")"
done

sprite-tools atlas cut/*.png -o atlas.png --json atlas.json
```

## Drop the repeated frames from a video extraction, then rewrite the tags

Video sampled at a fixed FPS repeats every pose that lasts longer than one sample. At 10fps, a pose held for 0.4 s arrives as four copies of one frame. The copies are often byte-identical, and sometimes a few levels apart after video compression. Tile the frames into a sheet with ffmpeg, tag the sheet, then dedupe with the tags so the ranges follow the renumbered frames:

```bash
# 32 frames at 10fps, tiled 8x4
ffmpeg -i walk.mp4 -vf "fps=10,tile=8x4" -frames:v 1 walk-sheet.png

sprite-tools tags walk-sheet.png --cols 8 --rows 4 \
  --tag idle=0-15 --tag walk=16-31:12:pingpong \
  -o walk-tags.json

sprite-tools dedupe walk-sheet.png --cols 8 --rows 4 --threshold 1 \
  --tags walk-tags.json --tags-out walk-tags-deduped.json \
  --sheet walk-deduped.png \
  -o walk-dedupe.json

jq '.removedCount, .warnings' walk-dedupe.json
```

`walk-tags-deduped.json` has the same shape as the tags file, with `grid` and `frameCount` set for `walk-deduped.png`. A clip with eight poses, each held for four samples, comes back as `idle` = frames 0-3 and `walk` = frames 4-7, each with a `shrank from 16 to 4` warning.

Pass the new grid to the next command. Grid detection can guess wrong on an opaque sheet, or on one whose last row ends in transparent cells. This GIF plays the whole deduped sheet at one rate, `idle` and `walk` together; it does not play a tag on its own:

```bash
GRID=$(jq -r '.grid | "--cols \(.cols) --rows \(.rows)"' walk-tags-deduped.json)
sprite-tools gif walk-deduped.png $GRID --fps 4 -o walk.gif
```

Notes:

- `--threshold 1` absorbs faint noise, such as rounding from video compression. Raise it towards 2-4 only if `removedCount` is lower than you expect, and check `groups[].distances` first. Above ~8, different poses start to merge.
- `--sheet` keeps `--sheet-cols` columns (default: the input's 8). When `uniqueCount` is not a multiple of that, the last row ends in transparent cells, and `gif` plays each of them as a blank frame. Run dedupe again with `--sheet-cols` set to `uniqueCount` to get a single row with no empty cells.
- If the tile has more cells than the clip has frames, ffmpeg fills the rest with identical blank cells. Dedupe collapses them into one blank frame, and `gif` plays that frame too.
- Check every tag for `"contiguous": false`, and play such a tag from its `frames` array. There are two causes. A frame in the tag matched an identical frame outside it, which `--respect-tags` prevents. Or the tag repeats one of its own poses non-adjacently, for example a walk cycle filmed over two loops, which `--respect-tags` cannot prevent. The warning names the cause.

## Trim then feed into collision (pipe chain)

```bash
cat hero.png \
  | sprite-tools trim - -o - --padding 1 \
  | sprite-tools collision - --tolerance 2 \
  > hero-collision.json
```

## Team colors: one hero sheet → a set of recolored sheets

Re-tint whole shading ramps instead of swapping colors one at a time, so the shading survives.

```bash
cat > teams.json <<'JSON'
{
  "version": 1,
  "colors": 12,
  "variants": [
    { "name": "Team Red",  "ramps": [{ "base": "#4d7faf", "to": "#af4d4d" }] },
    { "name": "Team Gold", "ramps": [{ "base": "#4d7faf", "to": "#c39b3a" }] },
    { "name": "Referee",   "ramps": [{ "base": "#4d7faf", "to": "#3d3d3d" }],
                           "swaps": { "#af4d4d": "#f2f2f2" } }
  ]
}
JSON

sprite-tools palette hero.png \
  --variants teams.json \
  --out-dir ./teams --name hero \
  --manifest ./teams/hero.json
```

Writes `teams/hero_team-red.png`, `teams/hero_team-gold.png`, `teams/hero_referee.png`, each stitched back to the source grid. `base` can be any shade of the target ramp — run `--ramps` first to see them:

```bash
sprite-tools palette hero.png --colors 12 --ramps | jq '.ramps'
```

## Batch: N enemy tints per character, packed into one atlas

```bash
mkdir -p tints
for f in characters/*.png; do
  sprite-tools palette "$f" --hue-variants 6 --out-dir tints > /dev/null
done

sprite-tools atlas tints/*.png -o enemies.png --json enemies.json
```

`--hue-variants 6` includes the 0° original, so each character contributes 6 files named `<name>_hue000.png` … `<name>_hue300.png`.

## Pack a folder of sprites into an atlas + manifest

```bash
sprite-tools atlas sprites/*.png \
  --padding 2 --pow2 \
  -o atlas.png --json atlas.json
```

## Extract frames → pack them into a new atlas

Useful when you want a different sheet layout:

```bash
sprite-tools slice hero.png --out-dir /tmp/hero-frames
sprite-tools atlas /tmp/hero-frames/*.png \
  -o hero-atlas.png --json hero-atlas.json
```

for f in characters/*.png; do

## PNG to a Godot 4 SpriteFrames resource

```bash
sprite-tools meta hero.png \
  --collision --pivot bottom-center \
  --tag idle=0-4 --tag walk=5-12 --tag attack=13-19 \
  --fps 12 \
  -o hero.json

sprite-tools export hero.json --format godot --res-path 'res://art/hero.png' -o hero.tres
```

Copy `hero.png` and `hero.tres` into the Godot project at the path `--res-path` names, let the editor import the PNG, then drop `hero.tres` onto an `AnimatedSprite2D`. The three tags become three animations. Collision and pivot are *not* in the `.tres` — Godot has no field for them — so read them out of `hero.json` and build the `CollisionPolygon2D` / node offset yourself. See [engine export](/docs/reference/engine-export).

Same thing without the intermediate file:

```bash
sprite-tools meta hero.png --collision --pivot bottom-center --tag idle=0-4 --fps 12 \
  | sprite-tools export - --format godot -o hero.tres
```

## Same metadata, four engines

```bash
sprite-tools meta hero.png --collision --pivot bottom-center \
  --tag idle=0-4 --tag walk=5-12 -o hero.json

sprite-tools export hero.json --format godot                       -o hero.tres
sprite-tools export hero.json --format unity  \
  --asset-path 'Assets/Art/hero.png' --ppu 48                      -o hero.png.meta
sprite-tools export hero.json --format aseprite                    -o hero-aseprite.json
sprite-tools export hero.json --format phaser                      -o hero-atlas.json
```

The Unity sidecar has to be named after the PNG it sits next to (`hero.png` → `hero.png.meta`); the CLI writes wherever `-o` points and will not correct you.

## Pack loose sprites, then export the packed atlas for Phaser

```bash
sprite-tools atlas sprites/*.png --padding 2 -o hero.png --json atlas.json
sprite-tools export atlas.json --format phaser -o hero-atlas.json
```

The texture name comes from the manifest's `atlas` field (`hero.png`), so `--texture` is not needed. Frame names come from the manifest keys, so they stay `hero_idle_0.png` rather than being renumbered. With no tags in the manifest, the atlas has frames and no `animations` map.

## Merge a packed atlas with tags, then export

`jq -s add` merges cleanly, and the exporter resolves the hybrid: the manifest supplies the rects, the header supplies the tags.

```bash
sprite-tools atlas frames/*.png -o hero.png --json atlas.json
sprite-tools tags hero-sheet.png --tag idle=0-4 --tag run=5-12:12 -o tags.json

jq -s add tags.json atlas.json \
  | sprite-tools export - --format phaser --texture hero.png -o hero-atlas.json
```

## Batch: a Godot resource per character folder

```bash
mkdir -p godot
for f in characters/*.png; do
  name=$(basename "$f" .png)
  sprite-tools meta "$f" --pivot bottom-center --tag idle=0-3 --fps 10 \
    | sprite-tools export - --format godot \
        --res-path "res://characters/${name}.png" -o "godot/${name}.tres"
done
```

## Consume the output in Node

```js
import metadata from "./hero.json" with { type: "json" };

for (const f of metadata.collision) {
  physicsBody.addPolygon(f.polygon, metadata.pivots[f.index].pivot);
}
for (const t of metadata.tags) {
  animator.clip(t.name, t.from, t.to, t.direction, t.fps);
}
```
