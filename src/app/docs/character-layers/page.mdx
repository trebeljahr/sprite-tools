# Prepare character layers

[Open Character Layers](/character-layers) to separate an illustration into editable parts before rigging it.

Start with a transparent character PNG. For a flat background, use [Background Removal](/background-removal) first.

## Review a draft

1. Open an image. The empty editor also offers a labeled geometric joint-test sample.
2. Import a reviewed plan, paste it with **Edit plan JSON**, or expand **AI preparation** and request an xAI draft.
3. Select a part. Edit its polygon, parent, pivot, tip and drawing order.
4. Complete its hidden area with xAI, or import an aligned completion PNG.
5. Use **Exploded** and **Bend test** to inspect overlaps and missing joint artwork.
6. Choose **Export layers**, then **Download project ZIP**. Open that ZIP later to restore the full project.

Drag polygon vertices to adjust a mask. Shift-click adds a vertex. Mask extraction updates when you release the pointer.
Choose **Joint pivot**, **Joint tip**, or **Ground origin**, then click its source-image position.
Undo and redo cover edits, completion imports and layer changes.

Part names and hierarchies are editable. Use the same format for creatures, wings, tails, hinges, props and weapons.
Save each sprite as its own ZIP; the editor restores one current local draft. No fixed humanoid skeleton is required.

Polygons include a part's hidden shape. Drawing order runs back to front in the plan.
A later polygon owns overlapping visible pixels. The inspector lists layers front to back.
Unassigned pixels remain in a separate layer and appear in the report.

## Preserve the source

Each visible source pixel belongs to one layer. Hidden pixels can be filled only beneath opaque foreground parts.
The original visible pixels and soft alpha edges remain unchanged. The rest-pose comparison reports changed pixels.

Completion images use the source canvas. Provider results can be resized only when their aspect ratio matches within 1.5%.
Imported completion PNGs must match the canvas exactly. The export separates original and reconstructed pixels.
Generated candidates use a chroma background selected to avoid the source colours. That background is removed before hidden pixels are accepted.
Local completion imports keep their own alpha; use a transparent PNG.

AI planning proposes polygons and joints. It does not provide pixel-accurate segmentation or a finished anatomical rig.
Review the masks, hand identity, draw order and completed anatomy. The bend test uses rigid parts and inherited joint rotation.
It does not preview mesh skinning, IK or final game animations. Qwen and other decomposition backends are not included.

## Control paid requests

Local edits, extraction, imports, bend tests and exports do not call a provider.
Browser AI actions send your image directly to xAI. The key stays in page memory and is excluded from saved projects.
Drafts and completion images stay in local IndexedDB until replaced. Export them for backup.

The planner uses `grok-4.20-0309-non-reasoning`, with at most 8,000 output tokens.
Its $0.05 planning reservation is an estimate, not a provider billing cap.
Completion uses `grok-imagine-image-2.0`, pinned to 1K and low quality.
Its estimate is $0.05 per part: one $0.01 input and one $0.04 output.
Prices checked on 21 October 2026 against [xAI pricing](https://docs.x.ai/developers/pricing).

Browser results are cached for the current page session. Accepted completion images persist with the project.
CLI/MCP results use a persistent content-addressed cache in the output directory.
No request is automatically retried. A stopped request may still be charged.
Check provider usage before retrying an uncertain request.

## Automate with the CLI

A supplied plan requires no API key or provider request:

```bash
sprite-tools character hero.png --plan plan.json --bend-tests all -o hero-layers
```

An AI draft requires `XAI_API_KEY` in the process environment and explicit paid opt-in:

```bash
sprite-tools character hero.png --ai --allow-paid --max-cost-usd 0.05 -o hero-layers
```

Review `hero-layers/plan.json`, then complete selected parts:

```bash
sprite-tools character hero.png --plan hero-layers/plan.json \
  --complete torso,upper-arm --allow-paid --max-cost-usd 0.10 -o hero-layers
```

`--complete all` processes parts with missing hidden pixels in sequence.
The cap covers estimated reservations for new requests in that invocation. Cached results cost no new reservation.
If the cap stops processing, the successful plan and completed parts remain exported.
`--retry-uncertain` explicitly permits another paid attempt after an uncertain dispatch. It may cause a duplicate charge.

Use `--completions files.json` to import local PNGs. That file maps part ids to PNG paths.
Headless source and imported completion images must be PNG files.
Provider JPEG/WebP results and resized images require installed `ffmpeg` and `ffprobe`.

## Automate with MCP

Call `sprite_prepare_character_layers` with `input_path`, `output_dir`, and either `plan`, `plan_path`, or `ai_draft: true`.
Optional `bend_test_parts` writes fixed +/-35-degree joint stress previews and clipping flags. These need visual review.
Optional `completion_paths` imports local PNGs. `complete_parts` selects paid hidden-area completion.

Paid calls also require `allow_paid: true`, `max_cost_usd`, and `XAI_API_KEY` in the MCP server environment.
Never put provider keys in tool arguments. Restart an existing MCP process to load the new tool.

## Plan format

Coordinates are source-image pixels. Ids are lowercase slugs and must be unique. `unassigned` is reserved.
Parents reference ids; hierarchy cycles are rejected. Parts can appear in any hierarchy order but must follow drawing order.

```json
{
  "version": 1,
  "width": 128,
  "height": 128,
  "origin": { "x": 64, "y": 120 },
  "parts": [{
    "id": "torso",
    "name": "Torso",
    "parent": null,
    "pivot": { "x": 64, "y": 80 },
    "tip": { "x": 64, "y": 40 },
    "polygon": [{ "x": 40, "y": 40 }, { "x": 85, "y": 40 }, { "x": 85, "y": 85 }, { "x": 40, "y": 85 }],
    "description": "Complete the coat behind the forearm."
  }],
  "notes": []
}
```

Limits: 32 parts, 128 vertices per part, four megapixels per canvas, and 32 million canvas pixels across parts.
Reduce image size or part count if that aggregate limit is exceeded.

## Export files

- `source.png`, `plan.json`: source artwork and editable preparation plan.
- `character.json`: format/version, canvas, origin, hierarchy, file paths, completion provenance and review report.
- `layers/`: composed parts, aligned to the common canvas.
- `visible/`: original source pixels owned by each part.
- `generated/`: accepted reconstructed pixels, including imported completions.
- `masks/`: areas hidden by opaque foreground layers.
- `completions/`: full accepted candidate images for later mask edits.
- `reconstruction.png`: assembled rest pose.
- `bend-tests/` and `bend-tests.json`: optional headless stress previews with angles, origin and potential clipping flags.

The bundle prepares artwork for a rigging tool. It is not a Godot Skeleton2D, Spine project, or baked animation export.


## Open a shared project link

A link such as `/character-layers?project=/sprites/hero.zip` opens a hosted project in any browser.
The ZIP must be hosted on the same site. Opening it does not require a provider key.
Edits remain in that browser's local draft. Export a ZIP to transfer them to another browser.
When a linked project replaces an existing draft, Undo restores that draft during the same session.

## Test animation movement

[Sprite Playground](/playground) loads an animation-set JSON with `?set=/sprites/animation-set.json`.
The set lists PNG sheets, frame sizes, a shared origin, frame durations and looping rules.
Sheets must use the declared grid. Sources remain unchanged.

Use **Play controller** to test A/D movement, Shift running, W/Space jumping, S/E rolling and F attacks.
Physics moves the shared origin; the animation supplies local body motion.
Jumps retain horizontal momentum. Press F during a roll to queue a stab.
Another F near attack recovery queues the next attack. Escape releases keyboard control.
Input is captured only while the stage is focused. Losing focus clears held keys.

Use **Clips & transitions** to choose two actions and preview their transition.
**Switch at clip end** queues a selected action until the current cycle finishes.
Frame stepping, scrubbing and playback speed help review the transition.
The bindings map controller actions to clip names, so other characters can use the same controller.

Run and roll have explicitly labelled preview fallbacks when their bindings are empty.
A run fallback speeds up the walk cycle. A roll fallback transforms an idle pose; it is not finished roll artwork.
Replace these bindings with authored clips before production use.

Per-clip saturation, contrast and brightness affect preview rendering only.
**Run speed** adjusts sprinting immediately, from 400 to 2,400 world pixels per second. Walking stays at 350 px/s. **Run animation** sets milliseconds per complete run cycle independently of movement speed. **Save set settings** keeps both speeds, bindings and colour settings in JSON. It does not bake corrected PNGs or export a game controller.

This format also accepts the existing animation-set structure with `canvas`, `origin` and `clips`.
Optional `controller.bindings` maps `idle`, `walk`, `run`, `jump`, `roll`, `attack1`, `attack2` and `attack3` to clip ids.
Each clip can include `colour: { saturation: 1, contrast: 1, brightness: 1 }`.
Optional `controller.layerProject` links back to a same-site character ZIP.

Optional `controller.labels` overrides action names without changing their bindings. Source provenance and extra clip metadata survive a settings export.

### Distance-driven locomotion and scrolling

The playground has a 1280 × 600 viewport over a 7680px-wide world, with room in both directions from the starting point. The camera follows movement and jumping. Distant woodland, ruins and nearer trunks scroll at different parallax rates. Ground marks stay fixed in world space for checking foot contact.

Walking frame phase follows distance travelled. Running uses **Run animation** for the full-speed cycle length, stored as optional `controller.runCycleMs`; without it, the bound clip’s duration supplies the rhythm. Changing **Run speed** changes travel distance while keeping that cycle length. Acceleration slows cadence; blocked movement stops it. Attack, roll, idle and airborne timing remain independent. In **Animation bindings & colour**, select Walk to adjust **Stride distance**. Save set settings to retain the value.

An optional clip `locomotion` object stores `stridePixels` (world pixels per complete cycle), `phaseOffset` (0–1), and one `groundOffsets` Y correction per frame (source-art pixels). These settings work with arbitrary character sets. They calibrate flattened clips; they do not create foot IK or fix incorrect generated poses. Clip review uses the original durations, so controller cadence may differ from clip playback.

**When stopped → Hold last frame** stores `controller.restPose: "hold"`. The controller keeps playing the gait while braking, then holds the last displayed walk/run frame at its existing phase. Moving again resumes that phase. Attacks, rolls and landings finish and hold their final pose; jump, movement and combat input remain available. At startup, the first idle frame supplies a still pose. Authored idle transitions and the idle loop are bypassed in controller play; they remain available for isolated clip review. This changes playback only, with no image interpolation or generated artwork. A mid-stride foot can remain raised. Save set settings to reuse this choice with other character sets.

**When stopped → Play idle animation** uses the existing recovery behavior. This is the default for sets without `controller.restPose`.

When movement stops, the controller blends its last gait pose into idle over 240ms. Running keeps its gait while braking; releasing Shift with the direction key still held switches to walking. Finishing an attack, roll or landing also blends into idle. The idle clock continues through the end of the fade instead of restarting. New movement, a jump or an attack can interrupt this settling step. The idle loop keeps playing when the canvas is unfocused; input stays restricted to the focused canvas. This is a short pose crossfade using existing artwork, not an authored stopping clip or skeletal blend.


### Authored stop and landing transitions

`controller.idleTransitions` connects existing animation roles to dedicated, non-looping recovery clips. Each route names `from`, `exitFrame`, `clip`, and `idleFrame`; optional `leadMs` bounds the final step into the exit pose. Multiple routes from a gait let the controller choose the nearer forward foot contact. Set the bridge's first image to that exact exit pose and its last image to the exact idle entry. The controller plays source poses into the exit, then the recovery clip, then idle. Configured routes use no dissolve. Movement, jump, roll and attack can interrupt recovery immediately. Jump routes start at ground contact instead of squeezing recovery into the fallback landing timer.

```json
{
  "controller": {
    "idleTransitions": [
      { "from": "walk", "exitFrame": 1, "clip": "walk-stop-front", "idleFrame": 0, "leadMs": 180 },
      { "from": "walk", "exitFrame": 11, "clip": "walk-stop-rear", "idleFrame": 0, "leadMs": 180 },
      { "from": "run", "exitFrame": 7, "clip": "run-stop", "idleFrame": 0, "leadMs": 180 },
      { "from": "jump", "exitFrame": 17, "clip": "land-recover", "idleFrame": 0, "leadMs": 100 }
    ]
  }
}
```

**Stop and landing transitions** buttons review the exact exit pose, recovery clip and idle entry. The playback speed selector also slows this review. Geometry and route validation cannot certify natural motion: inspect the step, planted foot, weapon hand, body volume and both joins. A route's bounded lead can accelerate the final portion of a gait; author additional exit variants when that is visible.

A clip can store a losslessly cropped sheet with `frameCrop: { x, y, width, height }`. Each physical sheet cell has that width and height; the rectangle locates it inside the set's unchanged virtual `canvas`. Origins and movement stay in virtual coordinates. This saves transparent-sheet memory without resizing or moving painted pixels. The loader validates the physical PNG grid, crop bounds and total decoded pixel budget. Set a route’s `enabled: false` to keep an unapproved trial available in transition review while excluding it from controller playback. Settings export retains crops and transition routes. Sets without routes retain the earlier fallback behavior.

### Bake guided inbetween frames locally

The CLI can add intermediate poses without a provider request:

```sh
sprite-tools inbetween exit.png idle.png --recipe guides.json -o recovery.png --json recovery.json
```

Both PNGs use the same canvas and ground origin. A recipe names matching directed lines on both poses:

```json
{
  "version": 1,
  "frames": 6,
  "durationMs": 240,
  "easing": "smoothstep",
  "guides": [
    { "name": "sword", "from": [[120, 80], [180, 110]], "to": [[118, 82], [178, 112]] }
  ]
}
```

Use several guides for the head, torso, limbs, weapon and clothing. Keep each line's endpoint order consistent. Coordinates refer to pixels within the PNG. The tool moves both endpoint textures toward each intermediate pose before blending them, using premultiplied alpha at edges. It keeps both endpoint frames unchanged and outputs `frames + 2` cells, timing metadata and the recipe. Output canvases must match and the packed sheet is limited to 32 million pixels.

Put these frames in a separate non-looping recovery clip. Appending idle recovery to a looping walk or run would play the stop on every stride. Bind the recovery with `controller.idleTransitions` and review it in the playground. Existing sheets, timing and bindings remain under your control.

Guides require manual placement. Warping cannot paint hidden anatomy or reliably resolve crossing arms, changing silhouettes or a weapon switching hands. Close poses usually need less correction; larger changes may stretch, soften or double details. Treat the output as a candidate and inspect both joins before production use. This command does not call an external service.


### Resume a recovery from the current phase

A route's optional `entryFrame` starts inside a shared recovery sheet. Its duration and isolated review include only that frame and the following frames. It defaults to zero. Give each source phase its own route, with `exitFrame` matching that phase and `leadMs: 0`, to enter the matching original pose immediately. Several routes can reuse one sheet without storing duplicate pixels.

For example, a sheet can contain the remaining forward walk poses, then a short settle. Phase-specific entries preserve the arm swing and its original durations instead of compressing a search for an exit pose or warping a forward arm through the torso. An optional `resumeFrame` restores the gait phase at the actual recovery ending; without it the controller uses `exitFrame`. Both indices are validated. New input still interrupts recovery immediately.

When a set has many recovery routes, **Recovery to review** selects a phase and **Preview recovery** plays it in isolation. Source-frame continuation cannot create a new stopping action: a long arm return may take much longer than a purpose-drawn stop. A close final-pose interpolation can still soften artwork.
