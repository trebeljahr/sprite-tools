# Contributing

Thanks for wanting to help — sprite-tools is intentionally small and composable, which makes it easy to extend.

## Repository layout

```
src/lib/            # pure algorithm modules (ImageData in, ImageData/JSON out)
  collision/
  pixel-art/
  palette/
  normal-map/
  atlas/
  pipeline/detect.ts
cli/                # CLI wrappers (commander + pngjs)
  commands/
  lib/
mcp/                # MCP server (@modelcontextprotocol/sdk + zod)
  tools.ts
src/app/            # Next.js app (tool pages + /docs)
tests/              # vitest suite
```

The **core invariant** is that every feature has four incarnations that share the same algorithm:

1. A pure function in `src/lib/`.
2. A CLI subcommand in `cli/commands/`.
3. An MCP tool in `mcp/tools.ts`.
4. A React page in `src/app/`.

All four produce the same JSON shape (for metadata tools) or the same PNG (for image tools).

## Add a new tool

Roughly:

1. **Algorithm module** in `src/lib/yourthing/yourthing.ts`. Function signature: `(imageData: ImageData, options: YourOptions) => ImageData | YourResult`. No DOM dependencies — the CLI and MCP server both run this in Node via the `ImageData` shim.
2. **Test** in `tests/yourthing.test.ts`. Exercise the pure function with small synthetic fixtures from `tests/helpers.ts`.
3. **CLI command** in `cli/commands/yourthing.ts` following the pattern of the others (commander subcommand, `addHelpExtras` for examples + output shape).
4. **MCP tool** in `mcp/tools.ts` under `registerAllTools`.
5. **Web page** in `src/app/yourthing/page.tsx`, using `useSharedProjectSource()` to pick up the shared sheet. Mirror the JSON output shape of the CLI command.
6. **Docs**: add an entry to `src/app/docs/_nav.ts` and a `page.mdx` under the right section.

## Run it locally

The repo uses **pnpm** — `pnpm install` at the root sets up the web app, CLI, and MCP server in one shot.

```bash
pnpm install
pnpm dev                       # Next.js dev server for the web app (http://localhost:3471)
pnpm cli:dev -- info some.png  # run the CLI via tsx, no build
pnpm mcp:dev                   # run the MCP server over stdio for local testing
pnpm test                      # vitest
pnpm cli:build                 # compiled CLI at dist/cli/index.js
pnpm mcp:build                 # compiled MCP at dist/mcp/index.js
pnpm install-local             # build + symlink as a global `sprite-tools` / `sprite-tools-mcp`
```

## Code style

- TypeScript strict mode, no `any` unless justified.
- Pure algorithm functions never reach for browser or Node globals — they take `ImageData` in and return data out.
- Commander CLI: use `parseIntArg` / `parseFloatArg` helpers for numeric options. Every new command should call `addHelpExtras` with both **Examples** and **Output shape** blocks.
- MCP tool: use Zod schemas for inputs; let MCP derive the JSON schema. Validate inside the handler only for things Zod can't express.
- Web pages: the shared `useSharedProjectSource()` hook is the only way to access the upload — don't add new `useState<File>` for source files.

## Tests

Every pure algorithm module has a `tests/*.test.ts`. If you're adding a new one, mirror the pattern — construct tiny `ImageData` fixtures in-memory via `tests/helpers.ts` and assert on the outputs. Run `pnpm test`.

## Pull requests

- Keep PRs small and focused. If you're adding a tool, one PR per tool is easier to review than one mega-PR.
- Update the docs in the same PR as the feature.
- Run `pnpm test && pnpm cli:build && pnpm mcp:build` before opening.

## Releasing

Maintainer-only. The published artifact is `@trebeljahr/sprite-tools` on npm — the root `package.json`'s `files` whitelist ships only the compiled CLI, MCP, and shared algorithm modules. No Next.js code or web-app deps make it into the tarball.

```bash
pnpm release        # patch (default)
pnpm release:minor
pnpm release:major
```

Each command:

1. `release-prep` refuses to start unless the working tree is clean and the local version is ahead of (or equal to) the npm registry.
2. `release-bump` rewrites `package.json`, commits, and tags atomically.
3. `_release:finish` builds the CLI + MCP, typechecks, `npm publish`es, and pushes the tag.

`prepublishOnly` re-runs both builds as a final safety check before npm uploads.
