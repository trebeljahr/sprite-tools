# MCP tool catalog

Full input/output schema for each of the 19 MCP tools.

## `sprite_info`

Inputs: `{ input_path: string }`

Returns JSON:

```json
{ "source", "width", "height", "opaquePixels", "opaqueFraction",
  "contentBounds": {x,y,width,height}|null,
  "grid": {cols,rows,confidence} }
```

## `sprite_detect_grid`

Inputs: `{ input_path: string }`

Returns JSON:

```json
{ "source", "width", "height",
  "grid": {cols,rows}, "confidence": 0..1 }
```

## `sprite_slice`

Inputs:

```ts
{
  input_path: string,
  out_dir: string,
  cols?: number,
  rows?: number,
  name_pattern?: string   // printf-style, default "frame_%02d.png"
}
```

Writes one PNG per cell. Returns `{ source, frameWidth, frameHeight, grid, frameCount, paths: string[] }`.

## `sprite_trim`

Inputs:

```ts
{
  input_path: string,
  output_path: string,
  padding?: number   // default 0
}
```

Returns `{ source, output_path, sourceWidth, sourceHeight, trim: {x,y,width,height}, paddingKept }`.

## `sprite_remove_background`

Chroma-keys the background out of a sprite, or out of every cell of a sheet.

Inputs:

```ts
{
  input_path: string,
  output_path: string,
  cols?: number, rows?: number,          // auto-detected if omitted
  mode?: "transparent" | "solid",        // default "transparent"
  similarity?: number,                   // 0..150, default 30
  softness?: number,                     // 0..50,  default 10
  spill?: number,                        // 0..100, default 20
  choke?: number,                        // 0..5,   default 1
  color?: "#rrggbb",                     // key colour; omit to auto-detect per frame
  fill?: "#rrggbb",                      // flat fill for "solid"; omit to blend corner colours
  trim?: boolean,                        // default false
  trim_padding?: number                  // default 0
}
```

Writes PNG. Returns JSON:

```json
{ "source", "output_path",
  "sourceWidth", "sourceHeight", "width", "height",
  "grid": {cols,rows,detected},
  "frameCount", "frameWidth", "frameHeight",
  "backgroundColor": "#rrggbb"|null,
  "backgroundColorSource": "explicit"|"detected"|null,
  "distinctBackgroundColors": ["#rrggbb", ...],
  "transparentFraction": 0..1,
  "trim": {x,y,width,height}|null,
  "options": {...} }
```

`backgroundColor` and `transparentFraction` are there so an agent can tell whether the key actually took — a `transparentFraction` near 0 means nothing was removed.

Notes:

- Frames are sliced, keyed independently (background auto-detected per frame unless `color` is given), and restitched. A 1×1 grid is a single sprite.
- `trim` uses one crop rect shared by every frame — the union of the per-frame content bounds — so the cells still line up as a grid.
- `"solid"` output is fully opaque, so `trim` is a no-op there and no background colour is reported. `spill` and `choke` are ignored by the solid path.
- See the [Background Removal page](/docs/web/background-removal) for what each slider does and where colour keying breaks down.

## `sprite_generate_nine_slice`

Emits the four stretch insets of a panel sprite, plus the nine regions they imply.

Inputs:

```ts
{
  input_path: string,
  cols?: number, rows?: number,
  left?: number, right?: number, top?: number, bottom?: number,   // explicit insets
  alpha_threshold?: number,   // 0..255, default 8
  tolerance?: number,         // 0..1, default 0.02
  min_middle?: number,        // default 1
  from_9patch?: boolean,      // default false — read the .9.png marker border instead
  ninepatch_output_path?: string,   // also write frame 0 as a .9.png
  preview_output_path?: string,     // also write frame 0 stretched, to eyeball
  preview_width?: number,           // default 3x frame width
  preview_height?: number           // default 3x frame height
}
```

Returns JSON with `options` and a `nineSlice` array — `{index, cell, insets, detected, confidence, regions}` per frame, same shape as the CLI `nine-slice` command — plus `ninePatchPath` / `previewPath` when those writes were requested.

Notes:

- Sides you pass are used as-is; sides you omit are a **starting guess** derived from variance profiles, taking the longest run of near-identical adjacent columns and rows to be the stretchable middle. That holds up on panels with an obviously flat or repeated middle and falls apart on busy or gradient artwork, where it returns zeros with `confidence` 0. Setting `left`/`right`/`top`/`bottom` yourself is the real interface.
- Check `confidence` before trusting a guessed result — it is how much of each axis the flat run covered, worse axis wins. `detected` is `false` and `confidence` is `0` when nothing had to be guessed, either because all four sides were supplied or because they came off a `.9.png` border.
- `preview_output_path` is the closest thing to the web app's live preview: write it, look at it, and correct the insets rather than trusting the numbers alone.
- `regions` is always nine entries, row-major from `top-left` to `bottom-right`, tiling the frame exactly.
- `from_9patch: true` strips the 1 px Android marker border and reads the insets off it, which is exact. Exactly one contiguous run per edge is supported; multi-run or malformed files are rejected with a descriptive error.
- See the [Nine-slice page](/docs/web/nine-slice) for what the insets mean and how to verify them.

## `sprite_generate_tags`

Inputs:

```ts
{
  input_path: string,
  cols?: number, rows?: number,
  tags: Array<{
    name: string,
    from: number,
    to: number,
    direction?: "forward" | "reverse" | "pingpong",   // default "forward"
```

## `sprite_generate_meta`

One-shot: combines collision + pivot + tags + nine-slice. Each sub-section is optional; omitted sections are skipped in the output.

```ts
{
  input_path: string,
  cols?: number, rows?: number,
  collision?: { alpha_threshold?, simplify_tolerance?, convex_hull? },
  pivot?: { preset?, x?, y? },
  tags?: Array<{name, from, to, direction?, fps?}>,
  nine_slice?: {
    left?, right?, top?, bottom?,
    alpha_threshold?, tolerance?, min_middle?
  }
}
```

Passing `nine_slice` (even as an empty object) adds the `nineSlice` section, with the same guess-versus-explicit behaviour as `sprite_generate_nine_slice`. It does not do `.9.png` input or PNG output — use the dedicated tool for those.

## `sprite_detect_ramps`

Groups the extracted palette into **shading ramps** — the light-to-dark runs of shades an artist painted for one material. Clusters by hue in OKLCH; everything near-grey lands in a single achromatic ramp. Run it before `sprite_palette_variants` to see what is recolorable.

Inputs:

```ts
{
  input_path: string,
  cols?: number, rows?: number,
  colors?: number,          // 1..256, default 8
  hue_tolerance?: number    // 0..180 degrees, default 25
}
```

Returns JSON:

```json
{ "source", "frameWidth", "frameHeight",
  "grid": {cols,rows,detected},
  "options": { "colors": 8, "rampTolerance": 25 },
  "palette": ["#rrggbb", ...],
  "ramps": [
    { "index": 0,
      "base": "#4d7faf",
      "colors": ["#243b52", "#395f83", "#4d7faf", "#7ea6cf"],
      "achromatic": false }
  ] }
```

Notes:

- `colors` in a ramp are sorted ascending by perceptual lightness. `base` is the ramp's most saturated shade — but **any** hex in `colors` is a valid `base` handle for re-tinting.
- Every palette entry lands in exactly one ramp; the ramp lengths sum to the palette size.
- Ramps come back largest-first, so `index` is stable for a given palette and palette size.
- Raise `hue_tolerance` to merge neighbouring hues into one ramp, lower it to split a ramp that swallowed two materials.

## `sprite_palette_variants`

Writes a family of recolored copies — team colors, enemy tints, seasonal skins — plus a manifest. A variant is a recipe: a whole-palette `hue_shift`, per-ramp re-tints that move an entire shading ramp at once (preserving its lightness steps and the artist's shadow/highlight hue drift), and/or literal per-color `swaps`. For a single output from a handful of hand-picked substitutions, use `sprite_palette_swap` instead.

Inputs:

```ts
{
  input_path: string,
  output_dir: string,        // created if missing
  cols?: number, rows?: number,
  colors?: number,           // 1..256, default 8
  hue_tolerance?: number,    // 0..180 degrees, default 25
  name?: string,             // filename base, default: input basename
  manifest_path?: string,    // also write the manifest JSON here

  // exactly one of these two:
  variants?: Array<{
    name: string,
    swaps?: Array<{ from: "#rrggbb", to: "#rrggbb" }>,
    ramps?: Array<{ base: "#rrggbb", to: "#rrggbb" }>,   // base = ANY member hex
    hue_shift?: number                                   // degrees
  }>,
  hue_variants?: number,     // 1..64 evenly spaced rotations
  hue_step?: number          // override the 360/N spacing
}
```

Writes `<output_dir>/<name>_<slug>.png` per variant, stitched back to the source grid for sheets. Returns the manifest plus the written paths:

```json
{ "version": 1,
  "source", "frameWidth", "frameHeight",
  "grid": {cols,rows,detected},
  "options": { "colors": 12, "mode": "defs"|"hue", "rampTolerance": 25 },
  "palette": ["#rrggbb", ...],
  "ramps": [{ "index", "base", "colors", "achromatic" }, ...],
  "variants": [
    { "name": "Team Red",
      "slug": "team-red",
      "file": "hero_team-red.png",
      "hueShift": 180,
      "swaps": [{ "from": "#rrggbb", "to": "#rrggbb" }, ...] }
  ],
  "files": ["/abs/path/hero_team-red.png", ...],
  "manifest_path": "/abs/path/hero.json" }
```

Notes:

- Supply **exactly one** of `variants` / `hue_variants`; supplying both or neither is a validation error.
- `hue_variants: 8` produces 8 files including the 0° original — `hue000`, `hue045`, … `hue315`, zero-padded so filenames sort in hue order.
- Stages apply coarse-to-fine: `hue_shift` over the whole palette, then `ramps`, then `swaps`. A literal swap always wins for the same source color.
- Names are slugified (lowercase, non-alphanumerics collapsed to `-`) and must be unique **after** slugification. Hex is accepted with or without `#` in any case; three-digit shorthand is rejected.
- This surface takes `hue_shift` and arrays of `{from, to}` pairs; the CLI's `--variants` file uses `hueShift` and a `{"#from": "#to"}` map. Same semantics, converted at the boundary.
- `hueShift` appears in a manifest entry only for variants that had one. `file` is a filename; `files` are absolute, so they can be piped straight into `sprite_pack_atlas`.
- See the [Palette page](/docs/web/palette) for why this runs in OKLCH rather than HSL.

## `sprite_add_outline`

Draws an outer or inner outline around the sprite, or around every cell of a sheet.

Inputs:

```ts
{
  input_path: string,
  output_path: string,
  cols?: number, rows?: number,            // auto-detected if omitted
  style?: "outer" | "inner",               // default "outer"
  width?: number,                          // 0..64, default 1
  color?: "#rrggbb",                       // default "#000000"
  opacity?: number,                        // 0..1, default 1
  connectivity?: 4 | 8,                    // default 8
  alpha_threshold?: number,                // 0..255, default 8
  overflow?: "expand" | "clip"             // default "expand"
}
```

Writes PNG. Returns `{ source, output_path, grid, output_width, output_height, margin, options }`.

## `sprite_add_shadow`

Drops a blurred, offset silhouette underneath the sprite, or underneath every cell of a sheet.

Inputs:

```ts
{
  input_path: string,
  output_path: string,
  cols?: number, rows?: number,
  offset_x?: number,                       // -256..256, default 2
  offset_y?: number,                       // -256..256, default 2
  color?: "#rrggbb",                       // default "#000000"
  opacity?: number,                        // 0..1, default 0.5
  blur?: number,                           // 0..64 px box blur, default 0
  alpha_threshold?: number,                // 0..255, default 8
  overflow?: "expand" | "clip"             // default "expand"
}
```

Writes PNG. Returns the same shape as `sprite_add_outline`.

Notes for both tools:

- A pixel counts as sprite when its alpha is above `alpha_threshold`. The sprite is composited on top of the outline, so anti-aliased edges blend over it instead of being cut.
- `connectivity: 8` grows diagonally (square corners); `4` grows in Manhattan steps (mitred corners). They differ visibly on diagonal edges.
- `overflow: "expand"` pads the canvas by the margin the effect needs so nothing is cropped; `"clip"` keeps the source dimensions. The returned `margin` is `{left, top, right, bottom}` and is all zeros under `"clip"`.
- On a sheet the margin is computed once from the options — never from the pixels — and applied to every cell, so the output grid stays uniform.
- The two tools are separate passes. Chaining `sprite_add_outline` into `sprite_add_shadow` works and casts the shadow from the outlined silhouette, but each pass expands the canvas on its own, so the result is padded twice. The web app applies both in a single pass with one margin.
- See the [Outline & Shadow page](/docs/web/outline) for what each control does.

## `sprite_pack_atlas`

Inputs:

```ts
{
  input_paths: string[],   // 1+ sprite PNGs
  output_path: string,     // atlas.png
  json_path: string,       // atlas.json manifest
  padding?: number,        // default 2
  extrude?: number,        // edge bleed, default 1, clamped to padding
  power_of_two?: boolean,  // default false
  trim?: boolean           // default true
}
```

Writes atlas PNG + manifest JSON. Returns the manifest inline.

`extrude` repeats each sprite's edge pixels into the surrounding gutter so filtered sampling can't pull in transparent texels. It never exceeds `padding` — at `padding: 0` there is no gutter and extrusion does nothing. Frame rects in the manifest are unaffected.

## Common notes

- All paths are **absolute** by convention — MCP doesn't inherit a working directory from the chat.
- Metadata returns are JSON strings (one content block). Parse with `JSON.parse()` on the client side.
- Image-producing tools write to `output_path` and return metadata about the write (so the agent knows where the file is).
