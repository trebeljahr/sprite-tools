# MCP tool catalog

Full input/output schema for each of the 23 MCP tools.

## Grid args on sheet tools

Seventeen tools consume a sheet and accept the same grid block: `sprite_lint_sheet`, `sprite_slice`, `sprite_remove_background`, `sprite_find_duplicates`, `sprite_generate_collision`, `sprite_generate_pivot`, `sprite_generate_tags`, `sprite_generate_nine_slice`, `sprite_extract_palette`, `sprite_palette_swap`, `sprite_detect_ramps`, `sprite_palette_variants`, `sprite_pixelate`, `sprite_generate_normal_map`, `sprite_add_outline`, `sprite_add_shadow`, and `sprite_generate_meta`.

```ts
{
  cols?: number, rows?: number,   // auto-detected if omitted
  margin?: number,                // border in px around the whole sheet
  margin_x?: number,              // left+right border; beats margin
  margin_y?: number,              // top+bottom border; beats margin
  spacing?: number,               // gutter in px between cells, both axes
  spacing_x?: number,             // horizontal gutter; beats spacing
  spacing_y?: number              // vertical gutter; beats spacing
}
```

All six are whole pixels, zero or more. Sheets from Kenney, Tiled, and TexturePacker carry a border and a 1–2px gutter. Slicing one flush shifts every cell boundary, so each frame picks up a strip of its neighbour — it looks almost right, which is why it goes unnoticed. Call `sprite_detect_grid` first if you do not know the numbers; it reports them in the same units.

The args are per-axis — `margin_x` sets left and right together. `sprite_detect_grid` can report an asymmetric border, which no arg expresses; on such a sheet omit the margin args and let detection fill all four sides in.

Unless you pass both `cols` and `rows`, detection runs and fills in whatever you left out, padding included; pass both and detection is skipped, so padding you did not state is zero rather than inferred. Detected padding is a hint — if it does not tile the sheet it is dropped rather than raised — but padding *you* passed is an assertion, so numbers that do not divide come back as an error naming the actual pixel counts instead of a silently wrong slice. With no padding args the cell size is `floor(width / cols)`, exactly as before.

Every one of these tools reports the geometry it actually used:

```json
"grid": { "cols", "rows", "detected",
          "margin": {left,top,right,bottom},
          "spacing": {x,y} }
```

Inputs: `{ input_path: string }`

Returns JSON:

```json
{ "source", "width", "height", "opaquePixels", "opaqueFraction",
  "contentBounds": {x,y,width,height}|null,
  "grid": {cols, rows,
           "margin": {left,top,right,bottom},

           "confidence": 0..1} }
```

## `sprite_detect_grid`

Inputs: `{ input_path: string }`

Returns JSON:

```json
{ "source", "width", "height",
  "grid": {cols, rows,
           "margin": {left,top,right,bottom},
           "spacing": {x,y}},
  "confidence": 0..1 }
```

`margin` and `spacing` are always present and are all zeros for a flush sheet or one whose padding could not be read confidently. Pass them straight back into any sheet tool. Inference only fires when every content block on an axis is the same size and every gap between them is identical, so it reports zeros rather than a guess.

## `sprite_lint_sheet`

**Call this first on any sheet you did not make yourself.** It answers "what is this file and what is wrong with it" in one call — the grid it really has, the frame count, and nine rules' worth of findings — so no later tool has to guess at an interpretation.

Inputs:

```ts
{
  input_path: string,
  cols?: number, rows?: number,           // auto-detected if omitted
  margin?, margin_x?, margin_y?,          // grid block above; detection fills
  spacing?, spacing_x?, spacing_y?,       //   whatever you leave out
  disable_rules?: string[],               // rule ids to skip entirely
  only_rules?: string[],                  // run only these; every other rule off
  min_severity?: "error" | "warning" | "info",
  options?: {                             // per-rule threshold overrides
    [ruleId: string]: { [option: string]: number | string | boolean }
  }
}
```

Valid rule ids: `alpha-fringe`, `frame-bleed`, `pivot-drift`, `duplicate-frames`, `empty-cell`, `opaque-frame`, `non-power-of-two`, `palette-bloat`, `palette-near-duplicates`.

Returns JSON — a [`LintReport`](/docs/reference/json-schemas#lint) with one extra field, `ok`:

```json
{ "ok": true,
  "source", "width", "height", "frameWidth", "frameHeight",
  "grid": {cols,rows,detected,confidence,margin,spacing},
  "summary": { "errors", "warnings", "infos", "frameCount",
               "rulesRun": [ruleId],
               "rulesSkipped": [{rule, reason}] },
  "findings": [{ "rule", "severity", "message",
                 "frame": number|null, "cell": {row,col}|null,
                 "at": {x,y}|null, "region": {x,y,width,height}|null,
                 "data": {...} }] }
```

Notes:

- `ok` is `summary.errors === 0`. Only `frame-bleed` is error severity by default, so `ok: false` means the grid is wrong — fix that (pass `cols` / `rows`) before acting on anything else. A `severity` you set through `options` is held to the same enum, so `ok` can never be true alongside a finding graded outside it.
- `at` and `region` are **sheet-absolute** pixel coordinates, unlike `sprite_generate_collision` and `sprite_generate_pivot`, which are cell-relative. `data` carries the numbers behind `message`, so branch on `rule` and `data` rather than parsing prose.
- `summary.rulesSkipped` lists rules whose preconditions the sheet did not meet. It is normally non-empty on healthy art — binary alpha skips `alpha-fringe`, a small palette skips `palette-bloat` — and is not a failure.
- `min_severity` trims the `findings` list only; `summary` still counts the whole run, so you can see how much was held back. The CLI's `--severity` behaves identically.
- An unknown rule id in `disable_rules`, `only_rules`, or `options` comes back as a recoverable `unknown_rule_id` error naming `validRules`, rather than being silently ignored. Inside `options`, an unknown option name, a value of the wrong type, or a severity outside `error|warning|info` comes back the same way, as `invalid_rule_option` — so an override either applied or told you why not.
- Every rule has documented blind spots — see [what each rule will not catch](/docs/cli/reference#what-each-rule-will-not-catch). A clean report means these nine rules found nothing, not that the sheet is correct.

## `sprite_remove_background`

Chroma-keys the background out of a sprite, or out of every cell of a sheet.

Inputs:

```ts
{
  input_path: string,
  output_path: string,
  cols?: number, rows?: number,          // auto-detected if omitted
  margin?, margin_x?, margin_y?,         // see Grid args above
  spacing?, spacing_x?, spacing_y?,
  mode?: "transparent" | "solid",        // default "transparent"
  similarity?: number,                   // 0..150, default 30
  softness?: number,                     // 0..50,  default 10
  spill?: number,                        // 0..100, default 20
  choke?: number,                        // 0..5,   default 1
  color?: "#rrggbb",                     // key colour; omit to auto-detect per frame
  fill?: "#rrggbb",                      // flat fill for "solid"; omit to blend corner colours
  trim?: boolean,                        // default false
  trim_padding?: number                  // default 0
}
```

Writes PNG. Returns JSON:

```json
{ "source", "output_path",
  "sourceWidth", "sourceHeight", "width", "height",
  "grid": {cols,rows,detected,margin,spacing},
  "frameCount", "frameWidth", "frameHeight",
  "backgroundColor": "#rrggbb"|null,
  "backgroundColorSource": "explicit"|"detected"|null,
  "distinctBackgroundColors": ["#rrggbb", ...],
  "transparentFraction": 0..1,
  "trim": {x,y,width,height}|null,
  "options": {...} }
```

`backgroundColor` and `transparentFraction` are there so an agent can tell whether the key actually took — a `transparentFraction` near 0 means nothing was removed.

Notes:

- Frames are sliced, keyed independently (background auto-detected per frame unless `color` is given), and restitched. A 1×1 grid is a single sprite.
- `trim` uses one crop rect shared by every frame — the union of the per-frame content bounds — so the cells still line up as a grid.
- `"solid"` output is fully opaque, so `trim` is a no-op there and no background colour is reported. `spill` and `choke` are ignored by the solid path.
- See the [Background Removal page](/docs/web/background-removal) for what each slider does and where colour keying breaks down.

## `sprite_generate_nine_slice`

Emits the four stretch insets of a panel sprite, plus the nine regions they imply.

Inputs:

```ts
{
  input_path: string,
  cols?: number, rows?: number,
  left?: number, right?: number, top?: number, bottom?: number,   // explicit insets
  alpha_threshold?: number,   // 0..255, default 8
  tolerance?: number,         // 0..1, default 0.02
  min_middle?: number,        // default 1
  from_9patch?: boolean,      // default false — read the .9.png marker border instead
  ninepatch_output_path?: string,   // also write frame 0 as a .9.png
  preview_output_path?: string,     // also write frame 0 stretched, to eyeball
  preview_width?: number,           // default 3x frame width
  preview_height?: number           // default 3x frame height
}
```

Returns JSON with `options` and a `nineSlice` array — `{index, cell, insets, detected, confidence, regions}` per frame, same shape as the CLI `nine-slice` command — plus `ninePatchPath` / `previewPath` when those writes were requested.

Notes:

- Sides you pass are used as-is; sides you omit are a **starting guess** derived from variance profiles, taking the longest run of near-identical adjacent columns and rows to be the stretchable middle. That holds up on panels with an obviously flat or repeated middle and falls apart on busy or gradient artwork, where it returns zeros with `confidence` 0. Setting `left`/`right`/`top`/`bottom` yourself is the real interface.
- Check `confidence` before trusting a guessed result — it is how much of each axis the flat run covered, worse axis wins. `detected` is `false` and `confidence` is `0` when nothing had to be guessed, either because all four sides were supplied or because they came off a `.9.png` border.
- `preview_output_path` is the closest thing to the web app's live preview: write it, look at it, and correct the insets rather than trusting the numbers alone.
- `regions` is always nine entries, row-major from `top-left` to `bottom-right`, tiling the frame exactly.
- `from_9patch: true` strips the 1 px Android marker border and reads the insets off it, which is exact. Exactly one contiguous run per edge is supported; multi-run or malformed files are rejected with a descriptive error.
- See the [Nine-slice page](/docs/web/nine-slice) for what the insets mean and how to verify them.

## `sprite_generate_tags`

Inputs:

```ts
{
  input_path: string,
  cols?: number, rows?: number,
  margin?, margin_x?, margin_y?, spacing?, spacing_x?, spacing_y?,   // see Grid args above
  tags: Array<{
    name: string,
    from: number,
    to: number,
    direction?: "forward" | "reverse" | "pingpong",   // default "forward"
    fps?: number   // default 10
  }>,
  frame_durations?: Array<{
    from: number,    // first frame index of the hold (0-based)
    to?: number,     // last frame index, inclusive; omit to hold only `from`
    ms: number       // hold time in milliseconds
  }>
}
```

Returns JSON with the tags array echoed. This is sprite-tools' own shape, not an Aseprite file — feed it to `sprite_export_engine` for that.

### `frame_durations`

Optional. Holds individual frames longer than their tag's uniform `fps` — the key-pose-longer-than-in-between case. Ranges are inclusive and later entries win where they overlap. Indices are **sheet** frame indices, not offsets within a tag.

```json
[{ "from": 0, "ms": 250 }, { "from": 3, "to": 4, "ms": 180 }]
```

It is emitted as the document's global `frameDurations` array — one entry per frame, `null` where nothing was set — so uncovered frames fall back to the fps of whichever tag plays them. Omit the input for uniform fps timing; the `frameDurations` key is then absent and the output is unchanged from before the input existed. See [JSON schemas](/docs/reference/json-schemas#framedurations) for why durations are global per frame rather than per tag.

## `sprite_generate_meta`

One-shot: combines collision + pivot + tags + nine-slice. Each sub-section is optional; omitted sections are skipped in the output.

```ts
{
  input_path: string,
  cols?: number, rows?: number,
  margin?, margin_x?, margin_y?, spacing?, spacing_x?, spacing_y?,   // see Grid args above
  collision?: { alpha_threshold?, simplify_tolerance?, convex_hull? },
  pivot?: { preset?, x?, y? },
  tags?: Array<{name, from, to, direction?, fps?}>,
  nine_slice?: {
    left?, right?, top?, bottom?,
    alpha_threshold?, tolerance?, min_middle?
  },
  frame_durations?: Array<{ from: number, to?: number, ms: number }>
}
```

Passing `nine_slice` (even as an empty object) adds the `nineSlice` section, with the same guess-versus-explicit behaviour as `sprite_generate_nine_slice`. It does not do `.9.png` input or PNG output — use the dedicated tool for those.

`frame_durations` works exactly as it does on `sprite_generate_tags` and adds the same top-level `frameDurations` array to the combined document.

## `sprite_find_duplicates`

Finds duplicate and near-duplicate frames in a sheet. Optionally writes the sheet without them, and rewrites a tags file so the ranges follow the renumbered frames.

Inputs:

```ts
{
  input_path: string,
  ...grid args,                   // cols/rows/margin/spacing — see above
  threshold?: number,             // >= 0, default 0 (byte-identical only)
  output_path?: string,           // write the deduped sheet PNG; omit to only report
  sheet_cols?: number,            // columns in the written sheet; default: input cols, capped at frames kept
  tags_path?: string,             // { tags: [...], frameDurations?: [...] } (as sprite_generate_tags emits) or a bare array
  tags_output_path?: string,      // write the rewritten tags JSON; requires tags_path
  respect_tags?: boolean          // default false; requires tags_path
}
```

Returns JSON:

```json
{ "source", "output_path", "tags_source", "tags_output_path",
  "sourceWidth", "sourceHeight",
  "grid": {cols,rows,detected},
  "frameWidth", "frameHeight",
  "method": "exact"|"mae", "threshold",
  "frameCount", "uniqueCount", "removedCount",
  "groups": [{ "keep", "duplicates": [...], "distances": [...] }],
  "keptIndices": [oldIndex, ...],
  "remap": [newIndex, ...],
  "output": {path,width,height,cols,rows}|null,
  "tags": [{ "name", "from", "to", "direction"?, "fps"?, "frames": [...], "contiguous" }]|null,
  "warnings": [string, ...],
  "options": {threshold,respect_tags,sheet_cols,partitioned} }
```

`remap[oldIndex]` is the new index of the frame that stands in for that old frame. `distances[i]` is the distance between `duplicates[i]` and `keep`, rounded to 4 significant digits. 0 means byte-identical, and a non-zero distance never rounds to 0.

`tags_output_path` gets `{ source, frameWidth, frameHeight, grid, frameCount, tags, frameDurations?, warnings }`, where `source` is `output_path` (or `input_path` when none is given), `frameCount` is the deduped count, and `grid` is the written sheet's grid (the input grid when no `output_path` is given). `frameDurations` is present when the input document had one: each kept frame takes the first explicit hold in its group, lowest index first.

Notes:

- **Threshold.** threshold is the mean absolute difference per RGBA channel on a 0-255 scale, averaged over every channel of every pixel. 0 requires byte-identical frames. 1 means the average channel differs by 1/255 (~0.4%), the scale of rounding noise from lossy video compression or canvas alpha premultiplication. 2-4 absorbs a handful of stray pixels. Above ~8 visibly different poses start collapsing. The comparison is inclusive: distance `<=` threshold merges.
- **Alpha counts.** An alpha difference adds to the distance like any other channel. At threshold 0 an alpha-only change is never a duplicate. At a higher threshold it merges once its distance is at or below the threshold. RGB under a fully transparent pixel is read as 0. Frames of different sizes never match.
- **Matching.** Byte-identical frames merge first. When `threshold` is above 0, each remaining frame is then compared, in source order, with the first frame of each group found so far, and joins the first group within the threshold. It is never compared with other duplicates, so if a matches b and b matches c, but a does not match c, then a and c stay apart. Frames are never reordered, and the kept frame is the lowest index in its group.
- **Renumbering.** Removing a frame renumbers every frame after it, so tags written for the old sheet point at the wrong frames. Pass `tags_path` to rewrite them. Each tag's old range maps through `remap`, and runs of the same new index collapse into one, so a tag with adjacent duplicates gets shorter. Name, `direction`, and `fps` are kept. Tag `from`/`to` must be integers.
- **Non-contiguous tags.** A range can come back with gaps when a frame inside it matched a frame outside it, or when the tag repeats one of its own poses non-adjacently. Frames are not reordered or copied to close the gap. The tag's `frames` array is the authoritative play order, `from`/`to` are only its lowest and highest index, `contiguous` is `false`, and a warning names the tag and the cause.
- **`respect_tags`** confines merging to within each tag, so no range loses a frame to another animation. Untagged frames share one group; where tags overlap, the first tag listed wins and a warning says so. A tag can still come back non-contiguous when two non-adjacent frames inside it match each other.
- Warnings also report tags that shrank, collapsed to one frame, or had a range partly outside the sheet (clamped). A range entirely outside the sheet comes back with empty `frames`. Warnings also add a note when duplicates were found but nothing was written, or when rewritten tags were saved without a deduped sheet to match them.
- Call it without `output_path` first to see the groups and distances before you change anything.
- The CLI equivalent is [`sprite-tools dedupe`](/docs/cli/reference#dedupe). The CLI keeps `--sheet-cols` even when fewer frames remain, and pads the last row with transparent cells.

## `sprite_detect_ramps`

Groups the extracted palette into **shading ramps** — the light-to-dark runs of shades an artist painted for one material. Clusters by hue in OKLCH; everything near-grey lands in a single achromatic ramp. Run it before `sprite_palette_variants` to see what is recolorable.

Inputs:

```ts
{
  input_path: string,
  cols?: number, rows?: number,
  colors?: number,          // 1..256, default 8
  hue_tolerance?: number    // 0..180 degrees, default 25
}
```

Returns JSON:

```json
{ "source", "frameWidth", "frameHeight",
  "grid": {cols,rows,detected},
  "options": { "colors": 8, "rampTolerance": 25 },
  "palette": ["#rrggbb", ...],
  "ramps": [
    { "index": 0,
      "base": "#4d7faf",
      "colors": ["#243b52", "#395f83", "#4d7faf", "#7ea6cf"],
      "achromatic": false }
  ] }
```

Notes:

- `colors` in a ramp are sorted ascending by perceptual lightness. `base` is the ramp's most saturated shade — but **any** hex in `colors` is a valid `base` handle for re-tinting.
- Every palette entry lands in exactly one ramp; the ramp lengths sum to the palette size.
- Ramps come back largest-first, so `index` is stable for a given palette and palette size.
- Raise `hue_tolerance` to merge neighbouring hues into one ramp, lower it to split a ramp that swallowed two materials.

## `sprite_palette_variants`

Writes a family of recolored copies — team colors, enemy tints, seasonal skins — plus a manifest. A variant is a recipe: a whole-palette `hue_shift`, per-ramp re-tints that move an entire shading ramp at once (preserving its lightness steps and the artist's shadow/highlight hue drift), and/or literal per-color `swaps`. For a single output from a handful of hand-picked substitutions, use `sprite_palette_swap` instead.

Inputs:

```ts
{
  input_path: string,
  output_dir: string,        // created if missing
  cols?: number, rows?: number,
  colors?: number,           // 1..256, default 8
  hue_tolerance?: number,    // 0..180 degrees, default 25
  name?: string,             // filename base, default: input basename
  manifest_path?: string,    // also write the manifest JSON here

  // exactly one of these two:
  variants?: Array<{
    name: string,
    swaps?: Array<{ from: "#rrggbb", to: "#rrggbb" }>,
    ramps?: Array<{ base: "#rrggbb", to: "#rrggbb" }>,   // base = ANY member hex
    hue_shift?: number                                   // degrees
  }>,
  hue_variants?: number,     // 1..64 evenly spaced rotations
  hue_step?: number          // override the 360/N spacing
}
```

Writes `<output_dir>/<name>_<slug>.png` per variant, stitched back to the source grid for sheets. Returns the manifest plus the written paths:

```json
{ "version": 1,
  "source", "frameWidth", "frameHeight",
  "grid": {cols,rows,detected},
  "options": { "colors": 12, "mode": "defs"|"hue", "rampTolerance": 25 },
  "palette": ["#rrggbb", ...],
  "ramps": [{ "index", "base", "colors", "achromatic" }, ...],
  "variants": [
    { "name": "Team Red",
      "slug": "team-red",
      "file": "hero_team-red.png",
      "hueShift": 180,
      "swaps": [{ "from": "#rrggbb", "to": "#rrggbb" }, ...] }
  ],
  "files": ["/abs/path/hero_team-red.png", ...],
  "manifest_path": "/abs/path/hero.json" }
```

Notes:

- Supply **exactly one** of `variants` / `hue_variants`; supplying both or neither is a validation error.
- `hue_variants: 8` produces 8 files including the 0° original — `hue000`, `hue045`, … `hue315`, zero-padded so filenames sort in hue order.
- Stages apply coarse-to-fine: `hue_shift` over the whole palette, then `ramps`, then `swaps`. A literal swap always wins for the same source color.
- Names are slugified (lowercase, non-alphanumerics collapsed to `-`) and must be unique **after** slugification. Hex is accepted with or without `#` in any case; three-digit shorthand is rejected.
- This surface takes `hue_shift` and arrays of `{from, to}` pairs; the CLI's `--variants` file uses `hueShift` and a `{"#from": "#to"}` map. Same semantics, converted at the boundary.
- `hueShift` appears in a manifest entry only for variants that had one. `file` is a filename; `files` are absolute, so they can be piped straight into `sprite_pack_atlas`.
- See the [Palette page](/docs/web/palette) for why this runs in OKLCH rather than HSL.

## `sprite_pixelate`

Inputs:

```ts
{
  input_path: string,
  output_path: string,
  cols?: number, rows?: number,
  margin?, margin_x?, margin_y?, spacing?, spacing_x?, spacing_y?,   // see Grid args above
  pixel_size?: number,   // 1..64, default 4
  colors?: number,       // 0..256, default 16
  palette?: "none" | "gameboy" | "gameboy-pocket" | "mono" | "pico8" | "cga" | "nes",
  dither?: boolean,
  upscale?: boolean,     // default true — restore to SOURCE size, blocky
  upscale_algo?: "nearest" | "scale2x" | "scale3x" | "eagle" | "xbr",   // default "nearest"
  upscale_factor?: number   // 1..9, default 1 (off) — explicit magnification
}
```

`upscale` and `upscale_factor` are two different size controls. `upscale` (default `true`) only scales the pixelated frame back up to the **original image size** with nearest-neighbor blocks, so the output matches the input dimensions. `upscale_factor` above 1 is genuine magnification by that integer factor using `upscale_algo`, and it **replaces** the restore-to-source step, so the frame is never scaled twice and `upscale` no longer applies. At the default `1` nothing changes.

`upscale_algo` is ignored at factor 1. The algorithm's native step (2 for `scale2x`/`eagle`/`xbr`, 3 for `scale3x`) is applied as often as it divides the factor evenly, and any remainder is nearest-neighbor — so the factors that run through the filter end to end are 2, 4 and 8 for the 2× filters and 3 and 9 for `scale3x`, which is why the cap is 9. All five filters only copy existing source pixels, so no new colors are invented and transparency is preserved exactly. Details and picking guidance are in the [Pixelate guide](/docs/web/pixelate).

Writes PNG. Returns `{ source, output_path, grid, width, height, frameWidth, frameHeight, options }`. `width`/`height` are the written file's dimensions and `frameWidth`/`frameHeight` a single frame's, so a sheet reports both — there is no need to re-open the PNG to learn how big the result is.

## `sprite_add_outline`

Draws an outer or inner outline around the sprite, or around every cell of a sheet.

Inputs:

```ts
{

  output_path: string,
  cols?: number, rows?: number,            // auto-detected if omitted
  style?: "outer" | "inner",               // default "outer"

```

## `sprite_add_shadow`

Drops a blurred, offset silhouette underneath the sprite, or underneath every cell of a sheet.

Inputs:

```ts
{
  input_path: string,
  output_path: string,
  cols?: number, rows?: number,
  offset_x?: number,                       // -256..256, default 2
  offset_y?: number,                       // -256..256, default 2
  color?: "#rrggbb",                       // default "#000000"
  opacity?: number,                        // 0..1, default 0.5
  blur?: number,                           // 0..64 px box blur, default 0
  alpha_threshold?: number,                // 0..255, default 8
  overflow?: "expand" | "clip"             // default "expand"
}
```

Writes PNG. Returns the same shape as `sprite_add_outline`.

Notes for both tools:

- A pixel counts as sprite when its alpha is above `alpha_threshold`. The sprite is composited on top of the outline, so anti-aliased edges blend over it instead of being cut.
- `connectivity: 8` grows diagonally (square corners); `4` grows in Manhattan steps (mitred corners). They differ visibly on diagonal edges.
- `overflow: "expand"` pads the canvas by the margin the effect needs so nothing is cropped; `"clip"` keeps the source dimensions. The returned `margin` is `{left, top, right, bottom}` and is all zeros under `"clip"`.
- On a sheet the margin is computed once from the options — never from the pixels — and applied to every cell, so the output grid stays uniform.
- The two tools are separate passes. Chaining `sprite_add_outline` into `sprite_add_shadow` works and casts the shadow from the outlined silhouette, but each pass expands the canvas on its own, so the result is padded twice. The web app applies both in a single pass with one margin.
- See the [Outline & Shadow page](/docs/web/outline) for what each control does.

## `sprite_pack_atlas`

Inputs:

```ts
{
  input_paths: string[],   // 1+ sprite PNGs
  output_path: string,     // atlas.png
  json_path: string,       // atlas.json manifest
  padding?: number,        // default 2
  extrude?: number,        // edge bleed, default 1, clamped to padding
  power_of_two?: boolean,  // default false
  trim?: boolean           // default true
}
```

Writes atlas PNG + manifest JSON. Returns the manifest inline.

`extrude` repeats each sprite's edge pixels into the surrounding gutter so filtered sampling can't pull in transparent texels. It never exceeds `padding` — at `padding: 0` there is no gutter and extrusion does nothing. Frame rects in the manifest are unaffected.

## `sprite_export_engine`

Turns sprite-tools metadata into a file a game engine imports directly. No pixels are decoded or written; it is a JSON transform, so it is the last hop after `sprite_generate_meta` (or `sprite_generate_collision` + `sprite_generate_pivot` + `sprite_generate_tags`, or `sprite_pack_atlas`).

Inputs:

```ts
{
  // exactly one of these two:
  input_path?: string,             // a metadata JSON file on disk
  metadata?: object,               // the same document inline

  format: "godot" | "unity" | "aseprite" | "phaser",
  variant?: "spriteframes" | "atlastextures"   // godot, default "spriteframes"
          | "meta"                              // unity, the only one
          | "hash" | "array",                   // aseprite/phaser, default "hash"

  texture?: string,                // texture filename recorded in the output
  name_prefix?: string,            // frame-name stem
  fps?: number,                    // for frames no tag covers, default 10
  output_path?: string,            // file; a DIRECTORY for godot "atlastextures".
                                   // omit to get the content back inline

  godot?: {
    texture_path?, loop?, loop_mode?: "bool" | "int",
    pingpong?: "bake" | "native", default_animation_name?,
    default_alias?, load_steps?
  },
  unity?: {
    pixels_per_unit?, filter_mode?: 0|1|2, max_texture_size?,
    serialized_version?: 12|13, asset_path?, guid?,
    sprite_mesh_type?: 0|1, generate_fallback_physics_shape?, physics_shape?
  },
  aseprite?: {
    frame_names?: "index" | "aseprite" | "normalized",
    pivots?: "omit" | "slices", pivot_slice_name?,
    app?, version?, image?, pixel_format?: "RGBA8888" | "I8"
  },
  phaser?: {
    frame_names?: "keep" | "index", image?, pixel_format?, scale?,
    app?, version?, frame_tags?, animations?, anchors?, related_multi_packs?
  }
}
```

`format` is the only required field. Every nested option is optional and left undefined passes through to the module's own default, so the MCP schema never drifts from the library.

The document may be one command's output, several merged with `jq -s add`, a `meta` result, an `atlas` manifest, or a header+manifest hybrid. Collision polygons, pivots and tags attach by frame index; missing sections are skipped.

For a grid document, the tool reads the width and height of the PNG that `source` names from its header, when the file exists, and falls back to `sourceWidth`/`sourceHeight` in the document. `sprite_generate_collision`, `sprite_generate_pivot`, `sprite_generate_tags` and `sprite_generate_meta` record both. A grid that does not match that size is an error. A document with an `output_path` (the result of an image-writing tool such as `sprite_remove_background`) is refused, because its `grid` describes the input image. A `sprite_read_aseprite` result is the exception: its `output_path` equals its `source`, because it describes the sheet it wrote. A grid document with `source: null` names no image, so it is an error unless `texture` is given.

With `output_path`, writes the file and returns:

```json
{ "path", "format", "variant", "texture", "frameCount", "tagCount", "bytes" }
```

Without it, returns the exact generated bytes instead:

```json
{ "format", "variant", "texture", "frameCount", "tagCount", "bytes",
  "filename", "content" }
```

The `atlastextures` variant is one `.tres` per frame. When that yields more than one file, `output_path` is the directory to write them into, and the responses carry a `files` array: `[{ path, filename, bytes }]` when written, `[{ filename, content, bytes }]` inline. `path` is then the directory and `bytes` the total. A single-frame document yields one file, and `output_path` is then the file itself.

Default filenames: `<stem>.tres` for a Godot `spriteframes` export and `<frame name>.tres` per frame for `atlastextures`, `<texture>.meta` for Unity (`hero.png` → `hero.png.meta`), `<stem>.json` for Aseprite and Phaser.

Notes:

- Pass `unity.asset_path` for a real Unity export. The guid and every sprite id hash from it, so seeding off a bare filename lets two same-named PNGs in different folders collide.
- The tool does **not** read an existing `.meta` back. Overwriting one in a Unity project with a fresh guid detaches every reference to that asset — read its `guid:` line and pass it as `unity.guid`.
- Godot `.tres` files carry no pivots and no collision; the format has no field for either. They are still read out of the document (they set Unity pivots and physics shapes) but nothing reaches the Godot output.
- See [engine export](/docs/reference/engine-export) for generated examples of every format, the coordinate conventions, and each format's limitations.

## `sprite_read_aseprite`

Reads an Aseprite working file (`.ase` / `.aseprite`) and returns its tags, per-frame durations, layer tree, and palette. It can also composite the frames and write them as a sheet PNG, one PNG per frame, or both. With neither `output_path` nor `frames_dir`, it writes nothing to disk.

Inputs:

```ts
{
  input_path: string,                      // absolute path to a .ase or .aseprite file
  output_path?: string,                    // write the frames as one sprite sheet PNG
  frames_dir?: string,                     // write one PNG per exported frame
  filename_pattern?: string,               // inside frames_dir, default "frame_%02d.png"
  cols?: number,                           // sheet columns; default: every frame in one row
  tag?: string,                            // export only this animation tag's frames
  layers?: string[],                       // composite only these layer names
  include_hidden?: boolean,                // default false
  scale?: number                           // 1..16 nearest-neighbour upscale, default 1
}
```

Returns JSON:

```json
{ "source": "/abs/sheet.png"|null,
  "sourceWidth"|null, "sourceHeight"|null,
  "asepriteFile": "/abs/hero.aseprite",
  "frameWidth", "frameHeight",
  "grid": {cols, rows, detected: false},
  "frameCount", "documentFrameCount",
  "canvas": {width, height},
  "colorDepth": 32 | 16 | 8,
  "pixelRatio": {width, height},
  "tag": "name"|null,
  "frameDurations": [ms, ...],
  "tags":   [{ name, from, to,
               direction: "forward"|"reverse"|"pingpong"|"pingpong-reverse",
               repeat, color: "#rrggbb"|null }, ...],
  "frames": [{ index, sourceIndex, durationMs }, ...],
  "layers": [{ index, name, type: "image"|"group"|"tilemap",
               opacity, blendMode, visible, effectivelyVisible, reference,
               childLevel, parentIndex }, ...],
  "palette": ["#rrggbb" | "#rrggbbaa", ...],
  "warnings": [...],
  "output_path"|null, "sheetWidth"|null, "sheetHeight"|null,
  "frames_dir"|null, "frame_paths": [...],
  "options": { tag, layers, include_hidden, scale, cols, filename_pattern } }
```

Every key before `output_path` is the same document the CLI's [`sprite-tools aseprite`](/docs/cli/reference#aseprite) writes. The keys from `output_path` on are MCP-only.

Notes:

- `source` is the sheet PNG written to `output_path`, not the `.aseprite` file. `sourceWidth` / `sourceHeight` are its pixel size and equal `sheetWidth` / `sheetHeight`. Without `output_path` all three are `null`, also when `frames_dir` is set. The file that was read is `asepriteFile`.
- `frameDurations` has one duration in milliseconds per exported frame. It is the key `sprite_generate_tags` and `sprite_generate_meta` write; see [JSON schemas](/docs/reference/json-schemas#framedurations). `frames[].durationMs` carries the same numbers. Tags have no `fps`.
- `tag` works like the CLI's `--tag`. `frameCount` counts the exported frames and `documentFrameCount` counts every frame in the file. The returned `tags` ranges are rebased onto the exported frames, so they are 0-based and index the sheet you got. Tags outside the export are left out. `frames[].sourceIndex` points back into the file.
- `layers` matches exact names. A group name selects every layer inside it. An unknown name is an error that lists the available names: `layers "X": no such layer. Available: ...` or `tag "X": no such tag. Available: ...`.
- `include_hidden` adds layers hidden in Aseprite. `effectivelyVisible` is `false` for a layer that is hidden itself or sits in a hidden group. `reference` is `true` for a reference layer.
- Reference layers are never composited, the same as an Aseprite export. `include_hidden` and `layers` do not bring them back.
- A `layers` selection that renders no pixels is an error: every named layer is a reference layer, or hidden without `include_hidden: true`. When another named layer does render, each such layer adds a warning instead. See [Layer selection](/docs/reference/aseprite#layer-selection).
- `frameWidth` / `frameHeight` include `scale`. `canvas` is the unscaled canvas size.
- `filename_pattern` needs a `%d` placeholder (`%02d`, `%03d`, ...) when more than one frame is exported. Without one, the call fails before it writes any file.
- `warnings` is always present. Check it: a tilemap layer or a damaged cel leaves a sheet with missing content and a warning, not an error. The common messages are listed on the [Aseprite files](/docs/reference/aseprite#warnings) page.
- With `output_path`, pass the result (inline as `metadata`, or saved to a file) to [`sprite_export_engine`](#sprite_export_engine). The engine file references the written sheet by name and size and keeps the frame durations and tag directions, including `pingpong-reverse`. Without `output_path`, pass `texture` too.

## Common notes

- All paths are **absolute** by convention — MCP doesn't inherit a working directory from the chat.
- Metadata returns are JSON strings (one content block). Parse with `JSON.parse()` on the client side.
- Image-producing tools write to `output_path` and return metadata about the write (so the agent knows where the file is).
